## 1. 왜 바꾸나

- 지금 트리는 **상품 × 칸 6개**(필터·회피·진입·조심·비중·매도)이고 칸마다 양식이 다르다 — 두 권에 맞춰 만든 것.
  칸에 안 맞는 말은 버려졌다(moneycopy 버려진 것 a 55개·b 63개 중 약 20개씩이 "비율·폭 미명시").
- 상품이 칸의 바깥 틀이라 같은 조건이 상품마다 복제됐다(moneycopy 51곳 — 원작자가 def 로 되접은 이유).
- 목표(기획의도 ②): **어떤 책이 와도** 원문 문장을 버리지 않고 담는 양식.

## 2. 최종 모양

```
{ version, products, names,
  rules: [ {label, ref, note?, on?, value?, then: [{when, do, qty?, repeat?}] | cond | skip, why?} ] }
```

> **충실성 원칙(§5 검사기가 강제): 표현 가능한 식은 반드시 추출한다.** `skip` 은 식으로 쓸 수 없는 **진짜 불가능한 잔여**
> (`데이터 없음`·`연산 없음`)에만 쓴다. 저자가 측정만 말하고 **행동(살지·팔지)을 안 준** 조건은 skip 이 아니라 **이름 조건**
> (`value`/`when` 만, 행동 없음)으로 남긴다 — 식이 트리에 살아남아 다른 규칙이 `{"rule": 이름}` 으로 참조한다.
> 한 문장에 식 되는 조각과 안 되는 조각이 섞이면 **쪼갠다**(식 조각 = 이름 조건/행동 규칙, 나머지 = skip).

| 맨 위 | 하는 일 |
|---|---|
| `version` | 양식 버전(3) — 코드가 옛 양식을 거부 |
| `products` | 판정할 종목 : `{index, ref | note}` — 기준지수(`$index`). 원문이 말했으면 `ref`, 아니면 `note` "운영 판단", 근거 없으면 `"?"`(검사기 정지 → 사용자 확인) |
| `names` | 이름 심볼(`$반도체대표주`) : `{syms, ref, note}` — 실제 종목은 여기 한 곳 |
| `rules` | **원문 판단 하나 = 규칙 하나** |

| 규칙 필드 | 하는 일 |
|---|---|
| `label` | **조건의 이름**(대상 + 상태, 행동 단어 넣지 않음). 다른 규칙이 이 이름으로 부른다. 책 안에서 유일 |
| `ref` · `note` | 원문 소절(여럿이면 `·`) · 해석/운영 판단 메모(판정엔 안 씀) |
| `on` | 원문이 **이름으로 지목한** 종목·이름 심볼. 생략 = `products` 전부 |
| `value` | 갈래들이 같이 보는 값(있을 때만). 갈래 안에서 `"$value"` |
| `then` | 갈래 목록 `[{when, do, qty?, repeat?}]` — **맞는 갈래 전부** 실행(각 갈래 한 번) |
| `cond` | **이름 조건** — `value`/`when` 만 있고 행동 없음(저자가 측정만 주고 행동 미명시). `then`·`skip` 둘 다 없는 규칙이 곧 이름 조건. 다른 규칙이 `{"rule": 이름}` 으로 참조. 판정 등급엔 직접 안 쓰임(참조될 때만) |
| `skip` | 못 옮긴 이유(`then`·`cond` 둘 다 불가일 때만) — `"연산 없음: …"` · `"데이터 없음: …"`. **식이 되면 skip 금지**(충실성 원칙 — §5 검사). `"저자 미명시: 행동"` 은 skip 이 아니라 이름 조건으로 |
| `why` | 심판이 a·b 중 고른 이유(최종 트리만) |

| 갈래 필드 | 하는 일 |
|---|---|
| `when` | 조건 — 지금 조건 문법 그대로 |
| `do` | **안 산다 · 산다 · 판다** |
| `qty` | 얼마나 `{of, x}` (산다·판다) |
| `repeat` | `true` = 조건이 다시 맞을 때마다(기본은 한 번) |

### 얼마나 (`qty`)

`qty` 는 **실제 저자가 준 숫자만** 담는 선택 칸이다(없으면 안 쓴다). `of` 는 그 숫자가 무엇의 비율인지:

| `of` | 뜻 | 원문 예 |
|---|---|---|
| `cash` | 총 투자금의 x % | "비중 30%" |
| `budget` | 이 종목 배정 금액의 x | "25%·30%·45% 로 나눈다" |
| `bought` | 지금까지 산 물량의 x | "산 물량의 30% 매도" · "같은 양 더 산다" |
| `held` | 지금 남은 물량의 x (1 = 전량) | "남은 것 절반" |

`x` = 숫자 · 식 · `"?"`. 지침: 정해진 몫 = `budget` · 계좌 대비 % = `cash` · 보유분 대비 = `bought`/`held`.
행동(판다)은 분명한데 **비율만 저자 미명시**면 `x:"?"`(🟡 사람이 답). 조건·행동 자체가 안 되는 것과 구별.

> **A 해결(2026-10-09 run3 검증) — 상대 사이징은 qty 아니라 입장(do/등급):** 저자가 숫자 없이 **크기만** 말한 것
> ("아주 작게"·"소액만"·"크게"·"비중 줄여라/키워라"·"확대/축소")은 **금액이 아니라 판정 입장**이다. qty 에 억지로 `"?"` 로
> 박지 않는다 → **do 동사(안 산다·산다)·등급**으로 해석한다(예: "20일선 아래 쉬거나 아주 작게"→`안 산다`, "3점 소액만"→`⚪관망`).
> 그래서 **옛 `order`(오늘 사려던 양의 x배) qty 종류는 폐지** — 시험 추출에서 `order` 는 3/3 전부 `"?"`(실제 숫자 0)로,
> 추상 입장을 숫자 자리에 박던 범인이었다. 크기 단계(소액<크게)를 등급에 더 담아야 할 만큼 자주 나오면 그때
> `grade_rules.json`(등급 사다리 유일 주인)에 한 줄 더한다(원칙 7). 등급은 이 한 파일에서만 — 별도 'v3 등급' 없음.

### 조건에 추가되는 것

| 표기 | 뜻 |
|---|---|
| `{"rule": "이름"}` | 그 이름의 조건을 가져다 씀 — 규칙이면 그 `value`(없으면 첫 갈래 `when`), 규칙 안의 이름 붙은 조각이면 그 조각 |
| `{"pos": "filled", "rule": "이름"}` | 그 규칙으로 산(판) 횟수 → "1차 다음 2차" · "~할 때마다" |
| `{"pos": "sold"}` | 지금까지 판 비율 → "절반까지만" (`sold < 0.5`) |
| 순위 | 후보 종목 중 이 종목의 순위 → "가장 강한 3개" |
| `"?"` | 저자가 안 준 숫자 — 조건이든 얼마나든 어디서든 (수량 자리의 `null` 없앰) |

포지션 값(`pos`: `ret`·`days`·`maxret`·`minret`·`filled`·`sold`)은 어느 규칙에서든 쓴다 — 보유가 없으면 그 갈래는 평가 안 함.

## 3. 없어지는 것

| 옛 것 | 어디로 |
|---|---|
| 칸 6개(`filter`…`exit`) | `do` 동사 셋 — 필터·회피 → 안 산다, 진입·비중 → 산다, **조심(줄여라) → 입장(안 산다/관망)**, 매도 → 판다 |
| `defs` | 이름 붙은 조각을 `{"rule": 이름}` 으로 부름(같은 것은 라벨 하나) |
| `weight`·`frac`·`sell`·`tranches` | `qty`(실제 숫자만 — `cash`/`budget`/`bought`/`held`) |
| `scale`(조심 배수) | 폐지 — 크기 조정은 입장/등급으로(옛 `order` 와 함께) |
| `null`(수량 미명시) | `"?"` |
| `upto` · `after` | `pos sold` · `pos filled` |
| `source`(book·extractor·sections_read) | 파일 위치·이름이 말함 · 커버리지는 검사기가 `ref` 로 직접 확인 |
| `unexpressed` | 식 되면 **이름 조건(`cond`)**, 식 안 되는 잔여만 `skip`(같은 규칙 목록 — a·b 짝짓기 쉬움). 충실성 원칙으로 "식 되는데 버림" 금지 |
| `review` | 규칙 안 `why` |

## 4. 판정·백테스트·화면

- 등급: **⛔ 안 산다**(안 산다 하나라도 걸림 — 옛 🚫·⛔ 합침, 사유는 규칙 이름) · **✅ 산다** · **⚪ 관망** · **🟡 확인 대기**(사람 확인) · **❔ 판정 불가**(데이터 부족).
  이 사다리의 유일한 주인은 `dsl/grade_rules.json`(화면·검사 다 여기 등급을 그대로 씀) — step 5 에서 옛 칸 기준(filter/avoid/entry)을 do 동사 기준으로 다시 쓴다.
- 산다가 여럿 걸리면 그냥 **산다**(사는 양은 각 산다 규칙의 `qty` 그대로 — 상대적 확대/축소 `order` 는 폐지, 크기는 입장/등급으로).
- 백테스트: 안 산 날은 **어느 규칙 때문인지** 규칙 이름별로 집계(옛 🚫/⛔ 두 칸보다 자세함).
- **표준 매도 없음**(C안): 판다 규칙이 하나도 없는 책은 매매 시뮬레이션 대신 **매수 신호 후 N일 보유 수익률**로만 평가, 화면에 "책에 매도 규칙 없음 — 매수 신호만 평가".
- 화면: `on` 없는 규칙 중 종목마다 값이 같은 조건은 "공통 조건"에 한 번 · 같은 조각이 여러 규칙에 나오면 처음 한 번만 펼치고 나머지 한 줄 · 사람 확인은 같은 이름 = 답 하나.

## 5. 중복·누락 막기 (검사기)

| 막는 것 | 예 | 방법 |
|---|---|---|
| 같은 식 두 벌 | "VIX ≥ 10" 을 두 규칙이 각자 | 정지 — 이름으로 부르게 |
| 같은 값, 기준만 다른 규칙 여럿 | VIX 10% 금지 · 20% 축소를 따로 | 정지 — 갈래 하나로 |
| 식은 다른데 매일 결과가 같음 | "VIX ≥ 10%" vs "VIX ÷ 어제 ≥ 1.1" | 시세로 돌려 봄 → 심판 확인 |
| 다른 규칙에 포함돼 효과 없음 | "달러·금리·VIX 동시 불편" ⊂ 장전 2점 이하 | 시세로 돌려 결과를 바꾼 날 0일 → 심판 확인 |
| 이름 | 겹침 · 없는 이름 부름 · 순환 · 행동 단어 섞임 | 정지 |
| 종목·심볼 | `products`/`names` 에 `"?"` 남음 · 이름 심볼이 `names` 에 없음 · `on` 종목이 `products` 에 없음 | 정지 |
| 누락 | 원문 판단 소절인데 어떤 규칙(`skip`·`cond` 포함)의 `ref` 에도 없음 | 정지 |
| **충실성 — 식 되는데 skip** | "20일 중 상승일 13일↑" 를 `skip:저자 미명시` 로(사실은 `sum(case)` 식) · `skip:데이터 없음` 인데 가격·분봉만 쓰는 식 | 정지 — 이름 조건/행동 규칙으로 뽑아라. skip 은 `데이터 없음`·`연산 없음` 잔여에만 |
| **반쪽 skip** | 한 소절에 식 되는 조각 + 안 되는 조각을 통째로 skip | 정지 — 식 조각은 추출, 안 되는 조각만 쪼개 skip |

a·b 비교는 **규칙 식으로만**(매매 시뮬레이션 비교 없음, A안).

## 6. 지침에 넣을 것

- **추출자**: 산출물은 이 파일 하나(지금의 `rules.json` + 트리 두 벌 → 하나). 같은 판정을 풀어 설명한 문장은 새 규칙이 아니라
  그 규칙의 `ref`·`note` 로. 같은 측정에 기준만 다르면 갈래 하나. 두 규칙 이상이 쓰는 조각은 이름 붙여 한 번만.
  "쉬거나 아주 작게"처럼 행동 범위면 보수적인 쪽 하나 + `note`.
- **심판**: 비교 단위 = 규칙. 고른 이유는 그 규칙 `why`. a·b 가 갈린 곳 = 판례 후보(진행자가 사용자 승인 후 지침으로).
- **사례 작성자**: 기대값 = 그날 그 종목의 결과(안 산다 / 산다 / 관망 / 판다), 칸 참·거짓이 아님.

## 7. 이번 범위 밖 — `skip`("연산 없음")으로 드러남

계좌 전체 기준("원금 −5%면 계좌 축소") · 종목 간 돈 이동("TQQQ 줄인 돈으로 UPRO") · 지난 매매 이력("수익 직후 2거래일 신규 매수 금지").
`skip` 의 "연산 없음"이 쌓이면 문법을 넓힐 거리로 사용자에게 보고.

## 9. 계산기 부품 정리 (같은 관점: 조합되면 지운다)

지표를 하나씩 코드로 만들지 않는다 — **기본 부품만 코드, 지표는 `COND_DSL` 조합 예시 줄**.

| 연산 | 판정 | 대체 조합 |
|---|---|---|
| `pct` | 삭제 | (값 ÷ lag(값,k) − 1) × 100 — "VIX ≥ 10%" vs "VIX ÷ 어제 ≥ 1.1" 같은 말 두 표기의 원인 |
| `rsi` | 삭제 | `smooth`·사칙연산 조합 |
| `count` | 삭제 | `sum`(case(c,1,0), n) |
| `streak` | 삭제 | `barssince`(not c) |
| `ma` | **삭제(확정 2026-10-09)** | `sum`(s,n) ÷ n — 식이 길어져도 순수 조합 유지(전용 연산 안 둠) |
| `ema` | 일반화 | `smooth`(s, 2/(n+1)) |
| `stdev` | 일반화 | `sqrt` + 사칙연산 |

새 기본 부품: **세션 시작**(그날 첫 봉 여부) · **`sumsince`**(minsince·maxsince 의 짝) · **`smooth`**(s, 비율 — EMA 2/(n+1), Wilder 1/n) ·
**`sqrt`** · **순위**(후보 종목 중 순위).
후보: **세션 경과 시간**(개장 후 분 — "장 시작 후 30분 이내"; 분봉 개수로 세면 빈 분봉에서 틀리므로 개장 캘린더 `md_feed.sessions().open` 기준).

조합 예시로만 두는 지표: ATR = smooth(max(고−저, |고−전일종가|, |저−전일종가|), 1/n) · VWAP = sumsince(세션 시작, 전형가×거래량) ÷
sumsince(세션 시작, 거래량) · 당일 고·저 = maxsince/minsince(세션 시작, …) · 시초가 = valuewhen(세션 시작, 시가) ·
첫 N분 고가 = valuewhen(세션 시작 후 N번째 봉, maxsince(세션 시작, 고가)) · 첫 눌림 저점 = valuewhen(첫 반등, minsince(세션 시작, 저가)).

`authoring/checklist/EXTRACTOR.md`(예시) · `verify/verify_primitives.py`(테스트) · `consumers/display/condition_view.py`(화면 문구 "20일선"·"RSI14"·
"k일 전 대비 변화율") · `verify/verify_view.py` · `books/*/tree_candidates/`(run3 로 대체). `signals/`·`consumers/backtest/` 에는 없음.
주인 표(verify_code)에 "지운 연산 이름이 어디든 나오면 정지" 줄을 넣어 남김 없이.

**구현은 pandas 로** — 지금 dsl/tradeTool.py(Cond)는 순수 파이썬 반복문. 기본 부품은 pandas 에 1:1(lag=`shift` · sum/highest/lowest=`rolling` ·
smooth=`ewm(alpha)` · since 계열=구간별 `cumsum/cummax/cummin` · 순위=`rank` · 3값 논리=nullable `boolean`(Kleene, NA=모름)).
우리 코드로 남는 것: `"?"`·수동·극성, asof·확정 일봉·일봉/분봉 혼합·워밍업. 지표 라이브러리(TA-Lib·pandas-ta)는 쓰지 않음
(지표 하나씩 들여오기 = 같은 실수, 계산 관례도 제각각) — 단 조합 예시가 맞는지 대조하는 **테스트 정답지**로만.
