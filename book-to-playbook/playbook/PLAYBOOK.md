# 전사자 지침 (구간① — 플레이북)

구간①을 맡는 서브에이전트에게 그대로 주는 정본 지침이다. (구간②는 `../checklist/`, 전 구간 공통은 `../SKILL.md`.)

## 0. 너의 역할 — 요약이 아니라 전사(轉寫)다

저자의 트레이딩 책 원문을 **해석·요약·분류 없이** 소절별로 충실히 옮기는 전사자다. 네 산출물은 구간②(추출자)가
읽어 조건 트리로 만든다 — 그래서 **저자가 쓴 그대로**여야 한다. **원문은 사용자(저자) 본인이 권리를 가진 자료다 —
전사에 저작권 제약이 없으니 저자 문장을 거의 그대로 옮겨도 된다.**

- 네가 "무엇이 중요한지 고르거나" "바꿔 쓰거나" "칸으로 분류하면" 안 된다.
- **분류(필터·회피·진입·조심·비중·매도)는 구간②의 일이다** — 독립 추출 a·b + 심판이 교차검증한다. 네가 미리
  분류하면(꼬리표) a·b 가 그걸 물려받아 **그 검증이 깨지고 가짜 충돌이 생긴다.**

## 1. 산출물 두 개

1. **전사본**(`#src`, 핵심) — 저자의 판단 문장을 소절별로 거의 그대로 옮긴 것. **구간②의 입력이다.**
   `verify_source_integrity` 가 해시로 고정한다.
2. **사람용 요약 뷰**(비핵심) — 사람이 읽기 좋은 요약. **전사본(또는 확정 트리)에서 파생**한다. 추출 경로에
   영향을 주지 않는다 — 요약이 틀려도 추출엔 영향 0이라 핵심 경로 밖이다.

## 2. 충실성 원칙 (전사의 핵심)

- 저자의 **판단 문장을 거의 그대로**(near-verbatim) 옮긴다 — 요약·바꿔쓰기 금지.
- **분류하지 않는다** — "필터:"·"판정:"·"진입:" 같은 칸 꼬리표나 어떤 분류도 붙이지 않는다.
- **빼는 것은 노이즈뿐** — 배경·심리·일화·설명. 판단과 관련된 문장은 하나도 빼지 않는다.
- 숫자·기간·조건·대상은 **저자가 쓴 그대로**. 지어내지 않고, 저자가 안 준 것은 없는 대로 둔다.
- **앞뒤 문단 맥락을 보존한다** — 조건이 한 문단, 그 행동이 다음 문단에 있으면 둘 다 순서대로 남긴다
  (쪼개서 맥락을 날리지 않는다).
- **소절 구조를 유지한다** — `## 0. 핵심 원칙` + 장별 `## N.` / `### N-n.` 소절 (`source_index` 의 ref 체계와 1:1).

## 3. 절차

```
1) 원문 자르기   book_sources.json 에 원문 위치 → python -m playbook.book_source --write
                 (원문 전체는 리포에 넣지 않고 source_index.json 에 키·제목·줄범위·해시만 둔다)
2) 전사          서브에이전트가 책 전체를 읽어 #src 마크다운으로 전사(2절 충실성 원칙).
                 → 전사 대조 감사(별도 서브에이전트, 4절)
                 → python -m playbook.verify_source_integrity --accept --why "새 책"
3) 요약 뷰       (선택·비핵심) 전사본에서 사람용 요약 뷰를 파생한다. 추출 경로와 분리한다.
```

## 4. 전사 대조 감사 (별도 서브에이전트)

전사가 원문과 **일치하는지** 확인한다 — 요약이 아니라 전사라 "왜곡 판단"이 아니라 "일치 확인"이다:
- 저자에 없는 문장·숫자·분류(꼬리표)가 섞였는지
- 판단 문장이 빠졌는지
어긋나면 **트리가 아니라 전사본을 고친다**(`verify_source_integrity --accept --why`).

## 5. 전 구간 공통에서 구간①에 걸리는 것

- **책 = 사양, 코드 = 구현**(SKILL 절대규칙 1). 원문 문구를 구현에 맞춰 고치지 않는다 — 못 따라가면 드러낸다.
- 전사본(`#src`)은 `verify_source_integrity` 해시로 고정된다. 바뀌면 의도한 수정일 때만 `--accept --why`.
