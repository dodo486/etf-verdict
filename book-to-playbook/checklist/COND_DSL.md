# 조건 트리 작성 지침 (books/&lt;slug&gt;/tree.json)

책의 매수 판단 규칙을 **조건 트리**로 옮기는 법. 평가기는 `shared/cond.py`, 문법 정본은 그 파일 docstring 이다.
트리는 사람이 아니라 기계가 실행한다 — 문법 밖의 키는 오류로 거부된다(조용히 무시되지 않는다).

## 1. 등급이 나오는 방식

상품마다 세 구역을 쓴다. 판정 시점 = 그날 **종가 직후**(다음 날 시가에 매수한다고 본다).

| 구역 | 뜻 | 등급 |
|---|---|---|
| `filter` | 이게 참이 아니면 아예 안 본다(추세·환경 전제) | 거짓 → 🚫 진입 금지 |
| `avoid` | 이게 참이면 사지 않는다(회피·과열·금지 자리) | 참 → ⛔ 보류 |
| `entry` | 이게 참이면 산다(매수 자리·확인 조건) | 참 → ✅ 매수 후보, 거짓 → ⚪ 관망 |

- 셋 다 **반드시** 쓴다. 조건이 없으면 `filter`/`entry` 는 `{"all": []}`(항상 참), `avoid` 는 `{"any": []}`(항상 거짓).
- 원문 구조를 그대로 적는다: "셋 중 하나" = `any`, "모두" = `all`, "넷 중 둘 이상" = `atleast`, "필수" = `all` 의 한 칸.
- 어느 구역에 넣을지는 **원문이 정한다**. 저자가 "~이면 쉬어라/관망"이라 하면 filter(전제), "~이면 사지 마라/미뤄라"면 avoid, "~이면 사라/들어갈 만하다"면 entry.

## 2. 수동(manual) — 자동으로 알 수 없는 조건

`{"manual": "사유"}`. 장중·시초가·프리마켓·분봉, 뉴스·실적 발표·재료, 사람이 차트를 보고 판단하라는 정성 표현.
엔진은 수동 조건을 '확인되면/안 되면' 두 번 평가해서:
- 확인 안 돼도 매수 → ✅, 확인돼야 매수 → 🟡 확인 대기(목록 표시), 확인돼도 안 됨 → 그 사유 등급.

**장 시작 전·장중 시점의 조건은 일봉으로 흉내 내지 말고 manual 로 둔다.** (선물 일봉의 전일 대비 등락은
'다음 날 개장 전 선물 방향'이 아니다.) 저자가 일봉 종가 기준으로 말한 것(예: "VIX가 전일 대비 10% 이상")만 자동으로 쓴다.

## 3. 숫자를 지어내지 않는다

- 저자가 준 숫자만 쓴다. 숫자 없이 "크게", "과하게", "많이" 라고만 했으면 그 조건은 `manual`("저자 미명시: …").
- 저자가 대상을 특정하지 않아 구현상 골라야 하는 것(예: "장비주" → AMAT)은 쓰되 `note` 에 "운영 판단"이라 적는다.
- 원문 사례(예: "7거래일 상승 후 3거래일 쉬고")의 숫자는 **규칙**이 아니라 예시다. 규칙 문장에 있는 숫자를 쓴다.

## 4. 문법 요약

```
숫자            3, 1.5
시세            {"px": "close"|"open"|"high"|"low"|"volume", "sym": "$self"}   sym 생략 = $self
산술            {"add"|"sub"|"mul"|"div": [a, b]}
창              {"ma"|"ema"|"stdev"|"highest"|"lowest"|"sum": [s, n]}   n 거래일(오늘 포함)
                {"lag": [s, k]}   k 거래일 전 값        {"pct": [s, k]}   k 거래일 전 대비 %
                {"rsi": [s, n]}
비교            {"gt"|"ge"|"lt"|"le": [a, b]}
논리            {"all": [..]} {"any": [..]} {"atleast": n, "of": [..]} {"not": c}
시간            {"count": [c, n]}      최근 n거래일(오늘 포함) 중 c 참인 날 수
                {"streak": c}          오늘부터 거꾸로 c 가 연속 참인 날 수
                {"barssince": c}       c 가 마지막으로 참이었던 날부터 지난 거래일(오늘 참 = 0)
                {"valuewhen": [c, s]}  c 가 마지막으로 참이었던 날의 s
                {"minsince"|"maxsince": [c, s]}  그날부터 오늘까지 s 의 최저/최고
여러 종목       {"across": {"syms": [..], "cond": c}}   c 참인 종목 수 — c 안에서 "$s" = 그 종목
수동            {"manual": "사유"}
재사용          {"def": "이름"}   (최상위 defs 에 정의)
메타            "label"(사람이 읽을 이름), "ref"(원문 소절 키, 예 "3-1"), "id", "note"
```

심볼: `$self` = 그 상품, `$index` = 상품의 기준 지수(상품의 `index` 필드), 그 외는 jhts 시세팀(`jhts.marketdata.candles`)이
일봉을 주는 심볼 코드 그대로 — 미국은 야후 심볼(예: `^NDX` `^GSPC` `^VIX` `^TNX`(10년물 금리, 값 = %) `NQ=F` `KRW=X`, 종목·ETF 티커),
국내는 6자리 종목코드. 쓰기 전에 그 심볼의 일봉이 실제로 나오는지 확인한다(안 나오면 검사기 ③ 이 '시세 없는 심볼'로 정지).

트리가 읽는 값은 **일봉 시세(시가·고가·저가·종가·거래량)뿐**이다. 분봉·호가·뉴스는 데이터가 없고,
투자자별 수급·공매도 잔고·등락 종목 수는 시세팀에 있어도 아직 트리 원시함수로 연결돼 있지 않다 —
이런 조건은 지금은 `manual` 로 두고(사유에 '데이터 미연결' 명시), 그런 책이 오면 원시함수를 추가한다.

## 5. 자주 틀리는 표현 — 이렇게 쓴다

| 원문 | 트리 |
|---|---|
| 종가가 20일선 위 | `{"gt": [{"px":"close"}, {"ma": [{"px":"close"}, 20]}]}` |
| 20일선 회복 후 2거래일 유지 | 회복일 + 2일 = 3일 연속 위: `{"ge": [{"streak": <20일선 위>}, 3]}` |
| 전고점 돌파 후 2~3거래일 버팀 | 돌파선 P = `{"highest": [{"lag": [C,1]}, N]}`, 돌파 = `{"gt": [C, P]}`, 돌파선 고정 = `{"valuewhen": [돌파, P]}`, 버팀 = `{"gt": [{"minsince": [돌파, C]}, 돌파선 고정]}` + 경과일 `{"add": [{"barssince": 돌파}, 1]}` |
| 고점 이후 2~4거래일 눌림 끝 반등 | 오늘 반등 `{"gt": [C, {"lag": [C,1]}]}` AND 어제까지 눌림 일수 = `{"lag": [{"barssince": {"ge": [C, {"highest": [C, N]}]}}, 1]}` 가 2~4 |
| 최근 10거래일 중 상승일 7일 이상 | `{"ge": [{"count": [{"gt": [C, {"lag": [C,1]}]}, 10]}, 7]}` |
| 5거래일 동안 20% 이상 | `{"ge": [{"pct": [C, 5]}, 20]}` |
| 거래량 전일 1.5배 이상 + 종가 고점 근처 | `{"all": [{"ge": [{"div": [V, {"lag": [V,1]}]}, 1.5]}, <종가 위치 조건 — 저자 숫자 없으면 manual>]}` |
| 3종목 중 2개 이상 상승 | `{"ge": [{"across": {"syms": [..], "cond": {"gt": [{"px":"close","sym":"$s"}, {"lag": [{"px":"close","sym":"$s"},1]}]}}}, 2]}` |

(C = `{"px":"close"}`, V = `{"px":"volume"}`. 지수(^NDX 등)는 거래량이 0/결측일 수 있다 — 거래량 조건은 거래되는 종목으로.)

## 6. 파일 형식

```json
{
  "version": 1,
  "source": {"book": "<slug>", "extractor": "a|b|채택", "sections_read": ["3-1", "..."]},
  "defs": {"C": {"px": "close"}},
  "products": {
    "TQQQ": {"index": "^NDX", "note": "...",
             "filter": {...}, "entry": {...}, "avoid": {...}}
  }
}
```

## 7. 원문 사례 시나리오 (books/&lt;slug&gt;/scenarios.json)

원문이 든 구체적 사례를 "이런 날이면 이 구역은 참/거짓이어야 한다"로 적는다. 트리를 **보지 않고** 원문만 보고 쓴다.

```json
{"scenarios": [
  {"name": "...", "ref": "3-1", "quote": "원문 한두 문장",
   "prod": "TQQQ", "section": "entry", "expect": true,
   "days": 60,
   "series": {"^NDX": {"close": [..]}, "TQQQ": {"close": [..], "volume": [..]}}}
]}
```

- 배열은 마지막 날(판정일)에 오른쪽 정렬된다. `days` 보다 짧으면 앞을 첫 값으로 채운다 — 마지막 며칠만 정확히 쓰면 된다.
- `high`/`low`/`open` 을 안 주면 종가와 같다고 본다. `volume` 을 안 주면 1,000,000 으로 일정.
- **안 적은 심볼은 '배경'**: 완만한 상승(하루 +0.1%), 고가 = 종가×1.002, 저가 = 종가×0.998, 거래량 일정.
  배경이 판정을 흔들 수 있는 심볼(그 구역이 보는 지수·종목)은 직접 적는다.
- 구역 전체의 결과를 기대값으로 쓴다(그 구역의 다른 조건도 그 상황에서 어떻게 될지 생각해서 쓴다).

## 8. 매도(청산) 규칙 — products.X.exit

보유 중인 포지션에 대해 매일 종가에 평가하고, 걸리면 **다음 날 시가**에 판다. 규칙마다 한 번만 적용된다.

```json
"exit": [
  {"label": "1차 익절", "ref": "7-5", "when": {"ge": [{"pos": "ret"}, 7]}, "sell": {"initial": 0.3}},
  {"label": "손절 재판단", "ref": "6-4", "when": {"le": [{"pos": "ret"}, -7]}, "sell": "all"},
  {"label": "반납 경고", "ref": "7-5", "when": {"all": [{"gt": [{"pos": "maxret"}, 0]},
      {"ge": [{"sub": [{"pos": "maxret"}, {"pos": "ret"}]}, {"mul": [{"pos": "maxret"}, 0.4]}]}]},
   "sell": {"remaining": 0.5}}
]
```

- 포지션 값(매도 규칙 안에서만): `{"pos": "ret"}` 진입가 대비 오늘 종가 수익률(%) · `"days"` 진입일부터 지난 거래일(진입일 0) ·
  `"maxret"`/`"minret"` 진입 후 종가 수익률의 최고/최저. 시장 조건(20일선 이탈 등)도 그대로 섞어 쓴다.
- `sell`: `"all"`(남은 전량) · `{"initial": f}`(처음 물량의 f) · `{"remaining": f}`(남은 물량의 f).
- 저자가 구간("7~10%")으로 말하면 그 구간에 **처음 닿는** 하한(7)으로 쓰고 note 에 적는다.
- "재판단", "검문", "판단한다"처럼 **판다는 말이 없으면** 매도 규칙이 아니다(옮기지 않는다). "축소"는 판다는 말이다 —
  비율이 없으면 `manual`(저자 미명시 비율)로 두지 말고 그 규칙을 옮기지 않고 보고에 적는다.
- 계좌 전체 기준(계좌 −5%, 현금 비중 등)·실적 발표일·뉴스는 상품 하나로 계산할 수 없다 — `manual` 로 두거나 옮기지 않는다.
- 안전장치를 끼우지 않는다. 저자가 안 준 손절·기간만료를 만들지 않는다(끝까지 안 걸리면 '미청산'이 그 규칙의 성적이다).
