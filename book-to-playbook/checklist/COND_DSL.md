# 조건 트리 작성 지침 (books/&lt;slug&gt;/tree.json)

조건 트리 = **체크리스트**. 책의 매매 판단 규칙을 기계가 실행하는 한 파일로 옮긴 것이다.
트리를 만드는 곳은 구간②(`checklist.verify_tree` 절차) 하나, 읽는 곳은 구간③(판정 엔진·백테스트) 하나다.
화면 체크리스트는 트리를 직접 읽지 않고 ③이 낸 판정 결과(`latest-verdict-<slug>.json`)만 그린다.

평가기는 `shared/cond.py`, 문법 정본은 그 파일 docstring 이다. 등급·사유는 `shared/tree_grade.py`,
체결 규약은 `shared/trades.py` — 만드는 쪽의 검사와 읽는 쪽의 판정이 **같은 코드**를 쓴다.
트리는 사람이 아니라 기계가 실행한다 — 문법 밖의 키는 오류로 거부된다(조용히 무시되지 않는다).

## 1. 판정의 종류 — 상품마다 여섯 칸

| 칸 | 묻는 것 | 형식 | 결과 |
|---|---|---|---|
| `filter` | 들어가도 되는 시장인가(추세·환경 전제) | 조건 | 거짓 → 🚫 진입 금지 |
| `avoid` | 사면 안 되는 자리인가(회피·과열·금지) | 조건 | 참 → ⛔ 보류 |
| `entry` | 살 자리인가(매수 자리·확인 조건) | 조건 | 참 → ✅ 매수 후보, 거짓 → ⚪ 관망 |
| `caution` | 사더라도 금액을 줄일까 | 규칙 목록 | 걸린 규칙마다 금액 × `scale` |
| `sizing` | 얼마나 살까(비중·분할) | 값 + 분할 목록 | 총 투자금 대비 % · 차수별 비율 |
| `exit` | 보유분을 언제 얼마나 팔까 | 규칙 목록 | 걸리면 다음 날 시가에 매도 |

- 여섯 칸 모두 **반드시** 쓴다(빠진 칸을 조용히 기본값으로 채우지 않는다). 조건이 없으면
  `filter`/`entry` 는 `{"all": []}`(항상 참), `avoid` 는 `{"any": []}`(항상 거짓), `caution`·`exit` 는 `[]`,
  `sizing` 은 `{"weight": null, "tranches": []}`(저자가 비중을 주지 않음).
- 판정 시점 = 그날 **봉이 끝난 직후**(일봉이면 종가 직후, 다음 날 시가에 체결한다고 본다).
- 원문 구조를 그대로 적는다: "셋 중 하나" = `any`, "모두" = `all`, "넷 중 둘 이상" = `atleast`, "필수" = `all` 의 한 칸.
- 어느 칸에 넣을지는 **원문이 정한다**. "~이면 쉬어라/관망" → filter, "~이면 사지 마라/미뤄라" → avoid,
  "~이면 사라/들어갈 만하다" → entry, "~이면 줄여서/소액만" → caution, "비중·분할" → sizing, "~이면 팔아라" → exit.

### 여러 상품이 같이 보는 판단 — `defs` 에 한 번만

시장 환경 점수, 공격/균형/방어 모드, 폭락 후 재진입 국면처럼 **상품 여럿이 같이 보는 판단**은 칸을 따로 두지 않고
최상위 `defs` 에 한 번 정의해 각 상품의 칸이 `{"def": "이름"}` 으로 참조한다. 상품마다 따로 쓰면 TQQQ 는 공격형인데
UPRO 는 방어형인 식으로 어긋난다. `defs` 의 노드에 `label` 을 달면 화면 맨 위 '공통 조건'에 한 번 보인다.

- 시장 환경: "2점 이하 관망" → 각 상품 `filter` 에 `{"not": {"def": "시장_관망"}}`, "3점 소액" → `caution` 규칙.
- 재진입: "폭락 후엔 이 조건으로 산다" → `entry` 의 한 갈래(`{"all": [{"def": "재진입_국면"}, ...]}`),
  "저점을 낮추는 중이면 금지" → `avoid`, "2개 전엔 큰돈 금지" → `caution`.
- 모드: 모드마다 서로 겹치지 않는 조건을 `defs` 에 둔다(방어 = VIX 급등, 균형 = 급등 아님 ∧ 반도체 과열,
  공격 = 둘 다 아님). 겹치지 않게 쓰는 것이 우선순위를 한 곳에서 정하는 방법이다. 각 상품 `sizing.weight` 가
  `case` 로 모드별 비중을 고른다.

## 2. 수동(manual) — 자동으로 알 수 없는 조건

`{"manual": "사유"}`. 장중·시초가·프리마켓·분봉(데이터 미연결), 뉴스·실적 발표·재료, 사람이 차트를 보고 판단하라는 정성 표현.

**묶음(all/any/atleast/not) 안이든 밖이든 수동 잎은 반드시 `label`(사람이 읽을 이름)을 가진다.** 없으면 화면에 "수동 확인"으로만 뜨거나(자동 잎은 hidden 으로 아예 사라져) 조용히 샌다. 비워 두면 생성기(`adopt`→`fill_missing_labels`)가 사유에서 제목을 파생해 채우고, `verify_tree`가 label 없는 수동 잎을 발견하면 정지한다.

엔진은 수동 조건을 '확인되면/안 되면' 두 번 평가해서:
- 확인 안 돼도 매수 → ✅, 확인돼야 매수 → 🟡 확인 대기(목록 표시), 확인돼도 안 됨 → 그 사유 등급.

**사유는 셋 중 하나로 시작한다** — 어디로 보내야 할지가 사유에서 바로 나온다:

| 사유 머리 | 뜻 | 다음 할 일 |
|---|---|---|
| `저자 미명시:` | 저자가 숫자·기준을 주지 않음("크게", "근처") | 없음 — 🟡 가 원문에 충실한 결과 |
| `데이터 없음:` | 계산할 값이 없음(분봉·실적 일정·뉴스·내 계좌) | jhts 수집 요청 / 데이터 연결 |
| `연산 없음:` | 값은 있는데 계산 도구가 없음 | 원시 연산 추가(검사기 ② 정답 대조 포함) |

**장 시작 전·장중 시점의 조건은 일봉으로 흉내 내지 않는다.** (선물 일봉의 전일 대비 등락은 '지금 개장 전 선물 방향'이
아니다.) 장중 값은 분봉 노드(`"tf": "1m"`)를 observe 로 감싸 쓰고(asof 기준 분봉), 그 값으로도 판정 기준이 안 서면
(저자가 숫자를 안 줌) manual 이다.

### 근거 숫자 — 수동 조건에 `measure`

저자가 **기준(threshold)만** 안 줬을 뿐 **값은 일봉으로 잴 수 있는** 수동 조건(예: "5일선 이격 과다",
"최근 5거래일 너무 올랐나", "환율이 20일 평균 위로 크게")은, 그 값을 계산하는 식을 `measure` 로 달아
**화면에 근거 숫자를 보여준다**. 그래야 사람이 깜깜이로 참/거짓을 고르지 않는다.

```json
{"manual": "저자 미명시: 5일선 이격 과다(폭 숫자 없음)", "label": "5일선 이격",
 "measure": {"mul": [100, {"sub": [{"div": [C, {"ma": [C, 5]}]}, 1]}]}}
```

- `measure` 는 보통의 값/조건 식이다(px·ma·pct·sub·div·lag·highest … 다 쓴다). 기준이 없으면 보통 **값 하나**
  (이격 %·5일 수익률 등)를 쓰고, 저자가 비교할 상수를 줬으면 비교식을 써도 된다.
- **노드는 그대로 수동이다.** `measure` 는 화면에 숫자(detail)를 붙일 뿐, 등급·수동 극성(not 아래 뒤집힘)·워밍업·
  자동 판정에는 **일절 끼지 않는다**(판정은 지금처럼 사람이 ● 참 / ○ 거짓으로 고른다). observe 와 다르다 —
  observe 는 값이 잡히면 자동 판정하지만, `measure` 는 **절대 자동 판정하지 않는다**.
- 값을 **일봉으로 못 재는** 수동(장중 분봉·내 계좌·실적 일정·뉴스)과, 일봉으로 계산 불가한 정성 항목(윗꼬리·
  '근처'·'반복' 등)에는 `measure` 를 **달지 않는다**(붙일 근거 숫자가 없다).

## 3. 숫자를 지어내지 않는다

- 저자가 준 숫자만 쓴다. 숫자 없이 "크게", "과하게", "많이" 라고만 했으면 그 조건은 `manual`("저자 미명시: …").
- 저자가 대상을 특정하지 않아 구현상 골라야 하는 것(예: "장비주" → AMAT)은 쓰되 `note` 에 "운영 판단"이라 적는다.
- 원문 사례(예: "7거래일 상승 후 3거래일 쉬고")의 숫자는 **규칙**이 아니라 예시다. 규칙 문장에 있는 숫자를 쓴다.
- 금액 축소 폭(`scale`)·비중(`weight`)도 같다. 저자가 "줄여라"만 하고 폭을 안 줬으면 `scale: null`.

## 4. 문법 요약

```
숫자            3, 1.5
시세            {"px": "close"|"open"|"high"|"low"|"volume", "sym": "$self", "tf": "1d"}   sym 생략 = $self, tf 생략 = 1d
산술            {"add"|"sub"|"mul"|"div"|"max"|"min": [a, b]}      max/min = 같은 날 두 값 중 큰/작은 값
                {"abs": a}
선택            {"case": [[c1, v1], [c2, v2], ...], "else": v}     위에서부터 처음 참인 조건의 값
                                                                  (앞 조건이 '모름'이면 결과도 모름)
창              {"ma"|"ema"|"stdev"|"highest"|"lowest"|"sum": [s, n]}   n 봉(오늘 포함)
                {"lag": [s, k]}   k 봉 전 값        {"pct": [s, k]}   k 봉 전 대비 %
                {"rsi": [s, n]}
비교            {"gt"|"ge"|"lt"|"le": [a, b]}
논리            {"all": [..]} {"any": [..]} {"atleast": n, "of": [..]} {"not": c}
시간            {"count": [c, n]}      최근 n봉(오늘 포함) 중 c 참인 봉 수
                {"streak": c}          오늘부터 거꾸로 c 가 연속 참인 봉 수
                {"barssince": c}       c 가 마지막으로 참이었던 봉부터 지난 봉 수(오늘 참 = 0)
                {"valuewhen": [c, s]}  c 가 마지막으로 참이었던 봉의 s
                {"minsince"|"maxsince": [c, s]}  그 봉부터 오늘까지 s 의 최저/최고
여러 종목       {"across": {"syms": [..], "cond": c}}   c 참인 종목 수 — c 안에서 "$s" = 그 종목
수동            {"manual": "사유"}
장중(분봉) 값   {"px": "close", "sym": "NQ=F", "tf": "1m"}   관측 시점(asof) 이하 마지막 분봉 — 분봉 데이터가
                없으면(아직 미연결·그날 분봉 미보관) 모름(None)이라 장중 조건은 observe 로 감싼다
관측·수동       {"observe": c, "manual": "사유"}   c 를 계산할 수 있으면 그 값, 관측값이 없으면 수동처럼 푼다
포지션          {"pos": "ret"|"days"|"maxret"|"minret"}   exit 와 sizing 의 2차 이후 분할에서만
재사용          {"def": "이름"}   (최상위 defs 에 정의)
메타            "label"(사람이 읽을 이름), "ref"(원문 소절 키, 예 "3-1"), "id", "note"
                "measure"(수동 조건에만 — 화면에 보여줄 근거 숫자 식, 2절. 등급·판정엔 안 쓴다)
```

조건을 숫자로 바꾸려면 `case` 를 쓴다: 상승일이면 1 = `{"case": [[{"gt": [C, {"lag": [C,1]}]}, 1]], "else": 0}`.
"하락일 낙폭 합 > 상승일 상승폭 합" = 하락일만 `abs(pct)` 를 더한 `sum` 과 상승일만 더한 `sum` 의 비교.

### 관측 시점(asof)에 본다 — 장중 조건은 observe

판정은 **사용자가 보는 그 순간(asof)** 기준이다. asof = 관측 시각(라이브 = 지금 또는 지정 시각, 백테스트 =
재생되는 각 시점). 각 시세 조회는 asof 로 자른다: **종가 조건 = asof 이하 마지막 확정 일봉**(고정),
**장중 조건 = asof 이하 마지막 분봉**(살아 있음). '아침 한 시점 고정 판정' 같은 건 없다.

"미국장 시작 전 10분", "장이 열리기 전"처럼 **장중에 보는** 조건은 분봉 노드(`"tf": "1m"`)로 적고
`{"observe": <조건>, "manual": "데이터 없음: …"}` 로 감싼다 — asof 기준 분봉이 있으면 자동, 분봉이 없으면
(아직 미연결·그날 분봉 미보관) 지금처럼 사람 확인(🟡). `python run.py watch [--every N]` 가 asof=지금 기준으로
N분마다 재판정·발행한다. 분봉이 연결되면 그대로 살아난다(코드·트리 변경 없이).

### 봉 단위(tf) — 일봉·분봉을 asof 축에서 자른다

모든 시세는 **봉**이고 봉의 길이(`tf`)는 시세 노드의 속성 하나다. `"1d"`(일봉) = asof 이하 마지막 확정 일봉,
`"1m"`(분봉) = asof 이하 마지막 분봉. 창·시간 연산의 n·k 는 '그 노드가 도는 봉' 기준으로 센다. 규칙은 하나:
**asof 이하의 값만 쓴다** — 그래서 미래를 볼 수 없다. 분봉 데이터가 연결되기 전까진 `"1m"` 조회는 늘 모름
(None)이라, 분봉이 필요한 조건은 observe 로 감싸 None→manual(🟡)로 정직하게 떨어진다(의도된 동작). 분봉의
다축 달력(그날의 분봉 구간 전체)은 후속 범위다 — 데이터 계약이 확정되면 `cond.minute_series` 한 곳만 채운다.

### 심볼과 수집

심볼: `$self` = 그 상품, `$index` = 상품의 기준 지수(상품의 `index` 필드), 그 외는 jhts 시세팀이 일봉을 주는
심볼 코드 그대로 — 미국은 야후 심볼(예: `^NDX` `^GSPC` `^VIX` `^TNX`(10년물 금리, 값 = %) `NQ=F` `KRW=X`, 종목·ETF 티커),
국내는 6자리 종목코드.

**수집 요청서는 따로 쓰지 않는다.** 필요한 시세는 트리에서 나온다: 구간③ 수집 단계가 `cond.symbols_of(tree)`
(여섯 칸 전부·`defs` 포함)로 심볼을 뽑아 `shared/md_feed.histories()` 한 곳에서 받는다. 시세가 없는 심볼은
jhts 수집 요청(`collection_requests`, requester `etf-verdict`, dataset `candles`)을 자동으로 남기고, 그 심볼을 쓰는
판정은 ❔ "시세 없음(수집 요청 #id)"으로 드러난다 — 채워지면 다음 판정부터 그대로 들어간다.

트리가 읽는 값은 지금 **일봉 시세(시가·고가·저가·종가·거래량)와 내 포지션(exit·분할)**이다. 투자자별 수급·공매도
잔고·등락 종목 수는 시세팀에 있어도 아직 원시 연산으로 연결돼 있지 않다 — 이런 조건은 `manual`("데이터 없음: …
연결 안 됨")로 두고, 그런 책이 오면 원시 연산을 추가한다.

## 5. 자주 틀리는 표현 — 이렇게 쓴다

| 원문 | 트리 |
|---|---|
| 종가가 20일선 위 | `{"gt": [{"px":"close"}, {"ma": [{"px":"close"}, 20]}]}` |
| 20일선 회복 후 2거래일 유지 | 회복일 + 2일 = 3일 연속 위: `{"ge": [{"streak": <20일선 위>}, 3]}` |
| 전고점 돌파 후 2~3거래일 버팀 | 돌파선 P = `{"highest": [{"lag": [C,1]}, N]}`, 돌파 = `{"gt": [C, P]}`, 돌파선 고정 = `{"valuewhen": [돌파, P]}`, 버팀 = `{"gt": [{"minsince": [돌파, C]}, 돌파선 고정]}` + 경과일 `{"add": [{"barssince": 돌파}, 1]}` |
| 고점 이후 2~4거래일 눌림 끝 반등 | 오늘 반등 `{"gt": [C, {"lag": [C,1]}]}` AND 어제까지 눌림 일수 = `{"lag": [{"barssince": {"ge": [C, {"highest": [C, N]}]}}, 1]}` 가 2~4 |
| 최근 10거래일 중 상승일 7일 이상 | `{"ge": [{"count": [{"gt": [C, {"lag": [C,1]}]}, 10]}, 7]}` |
| 5거래일 동안 20% 이상 | `{"ge": [{"pct": [C, 5]}, 20]}` |
| 윗꼬리 길이 | `{"sub": [{"px":"high"}, {"max": [{"px":"open"}, C]}]}` (길이 기준을 저자가 줬을 때만 비교) |
| 거래량 전일 1.5배 이상 + 종가 고점 근처 | `{"all": [{"ge": [{"div": [V, {"lag": [V,1]}]}, 1.5]}, <종가 위치 — 저자 숫자 없으면 manual>]}` |
| 3종목 중 2개 이상 상승 | `{"ge": [{"across": {"syms": [..], "cond": {"gt": [{"px":"close","sym":"$s"}, {"lag": [{"px":"close","sym":"$s"},1]}]}}}, 2]}` |

(C = `{"px":"close"}`, V = `{"px":"volume"}`. 지수(^NDX 등)는 거래량이 0/결측일 수 있다 — 거래량 조건은 거래되는 종목으로.)

## 6. 파일 형식

```json
{
  "version": 2,
  "source": {"book": "<slug>", "extractor": "a|b|채택", "sections_read": ["3-1", "..."]},
  "defs": {"C": {"px": "close"}},
  "products": {
    "TQQQ": {"index": "^NDX", "note": "...",
             "filter": {...}, "avoid": {...}, "entry": {...},
             "caution": [...], "sizing": {...}, "exit": [...]}
  }
}
```

## 7. 원문 사례 시나리오 (books/&lt;slug&gt;/scenarios.json)

원문이 든 구체적 사례를 "이런 날이면 이 칸은 참/거짓이어야 한다"로 적는다. 트리를 **보지 않고** 원문만 보고 쓴다.

```json
{"scenarios": [
  {"name": "...", "ref": "3-1", "quote": "원문 한두 문장",
   "prod": "TQQQ", "section": "entry", "expect": true,
   "days": 60,
   "series": {"^NDX": {"close": [..]}, "TQQQ": {"close": [..], "volume": [..]}}}
]}
```

- `section` 은 `filter`/`avoid`/`entry`, `caution`(기대값 = 이 상황이면 금액을 줄여야 하나 — 어느 조심 규칙이든 걸리면 참.
  트리를 보고 쓰는 회귀 사례만 `"rule": "<규칙 label>"` 로 한 규칙을 지목한다), `sizing`(기대값 = 그날 비중(%) 숫자).
- 배열은 마지막 날(판정일)에 오른쪽 정렬된다. `days` 보다 짧으면 앞을 첫 값으로 채운다 — 마지막 며칠만 정확히 쓰면 된다.
- `high`/`low`/`open` 을 안 주면 종가와 같다고 본다. `volume` 을 안 주면 1,000,000 으로 일정.
- **안 적은 심볼은 '배경'**: 완만한 상승(하루 +0.1%), 고가 = 종가×1.002, 저가 = 종가×0.998, 거래량 일정.
  배경이 판정을 흔들 수 있는 심볼(그 칸이 보는 지수·종목)은 직접 적는다.
- 칸 전체의 결과를 기대값으로 쓴다(그 칸의 다른 조건도 그 상황에서 어떻게 될지 생각해서 쓴다).

## 8. 조심(금액 축소) — products.X.caution

```json
"caution": [
  {"label": "시장 점수 3점 — 소액만", "ref": "2-6", "when": {"def": "시장_3점"}, "scale": null},
  {"label": "갭상승 추격 — 1차 금액 1/3", "ref": "7-3", "when": {...}, "scale": 0.3333}
]
```

- 매수 판단(✅·🟡)과 따로 평가한다. 걸린 규칙마다 그날 금액에 `scale` 을 곱한다. `scale: null` = 저자가 줄이라고만 하고
  폭을 안 줌 → 화면에 "줄일 폭 저자 미명시"로 보이고 금액 계산은 사람이 한다.
- "~이면 사지 마라"는 caution 이 아니라 avoid 다. caution 은 **사되 줄이는** 말일 때만.

## 9. 비중·분할 — products.X.sizing

```json
"sizing": {
  "label": "모드별 비중(6-2)", "ref": "6-2",
  "weight": {"case": [[{"def": "모드_방어"}, 14], [{"def": "모드_균형"}, 26]], "else": 34},
  "tranches": [
    {"label": "1차", "ref": "3-4", "frac": 0.25},
    {"label": "2차 — 돌파 후 2거래일 지지", "ref": "3-3", "frac": 0.30, "when": {...}},
    {"label": "3차", "ref": "3-4", "frac": 0.45, "when": {...}}
  ]
}
```

- `weight` = 총 투자금 대비 이 상품 비중(%), 숫자 식. 상품들의 `weight` 합은 어느 날이든 100 을 넘지 못한다
  (검사기가 정지시킨다). 현금 = 100 − 합 — 트리에 쓰지 않고 판정 단계가 계산한다. 저자가 비중을 안 주면 `null`.
- `tranches` = 분할 매수. `frac` 합은 1. 저자가 "나눠 산다"고만 하고 비율을 안 줬으면 차수마다 `"frac": null`
  (전부 null — 일부만 숫자는 안 된다). 비율을 지어내지 않는다 — 백테스트는 이때 전량 한 번 매수로 계산하고 그렇게 표시한다. 1차는 `when` 없이 매수 신호(✅·🟡) 날 산다. 2차 이후는 `when` 이 참인 날
  다음 봉 시가에 산다(차례대로 — 앞 차수를 안 샀으면 뒤 차수도 안 산다). 2차 이후 `when` 에서는 포지션 값을 쓴다.
  분할이 없으면 `[]` = 한 번에 전량.

## 10. 매도(청산) 규칙 — products.X.exit

보유 중인 포지션에 대해 매일 종가에 평가하고, 걸리면 **다음 날 시가**에 판다. 규칙마다 한 번만 적용된다.

```json
"exit": [
  {"label": "1차 익절", "ref": "7-5", "when": {"ge": [{"pos": "ret"}, 7]}, "sell": {"initial": 0.3}},
  {"label": "손절 재판단", "ref": "6-4", "when": {"le": [{"pos": "ret"}, -7]}, "sell": "all"},
  {"label": "반납 경고", "ref": "7-5", "when": {"all": [{"gt": [{"pos": "maxret"}, 0]},
      {"ge": [{"sub": [{"pos": "maxret"}, {"pos": "ret"}]}, {"mul": [{"pos": "maxret"}, 0.4]}]}]},
   "sell": {"remaining": 0.5}}
]
```

- 포지션 값: `{"pos": "ret"}` 평균 매입가 대비 오늘 종가 수익률(%) · `"days"` 첫 매수일부터 지난 봉 수(첫 매수일 0) ·
  `"maxret"`/`"minret"` 첫 매수 후 종가 수익률의 최고/최저. 시장 조건(20일선 이탈 등)도 그대로 섞어 쓴다.
- `sell`: `"all"`(남은 전량) · `{"initial": f}`(그때까지 산 물량의 f) · `{"remaining": f}`(남은 물량의 f).
- 저자가 구간("7~10%")으로 말하면 그 구간에 **처음 닿는** 하한(7)으로 쓰고 note 에 적는다.
- "재판단", "검문", "판단한다"처럼 **판다는 말이 없으면** 매도 규칙이 아니다(옮기지 않는다). "축소"는 판다는 말이다 —
  비율이 없으면 그 규칙을 옮기지 않고 보고에 적는다.
- 계좌 전체 기준(계좌 −5%, 현금 비중 등)·실적 발표일·뉴스는 상품 하나로 계산할 수 없다 — `manual` 로 두거나 옮기지 않는다.
- 안전장치를 끼우지 않는다. 저자가 안 준 손절·기간만료를 만들지 않는다(끝까지 안 걸리면 '미청산'이 그 규칙의 성적이다).

### 내 포지션 (books/&lt;slug&gt;/positions.json — 커밋하지 않음)

```json
{"positions": [{"prod": "TQQQ", "entry_date": "20260915", "entry_px": 81.2}]}
```

화면의 청산·분할 판정은 이 파일의 보유분에 대해 낸다. 없으면 규칙 목록만 보인다. 개인 정보라 `.gitignore` 대상이고
공개 페이지에는 실리지 않는다(로컬 서버 화면에서만 보인다).

## 11. 트리를 만드는 절차 (구간②, 사람 없이)

1. 서로 문맥을 공유하지 않는 추출자 2명이 **플레이북만 보고** `tree_candidates/a.json`·`b.json` 을 쓴다
   (매도 규칙은 `exit_a.json`·`exit_b.json`). 표현 못 한 규칙은 각자 `unexpressed` 목록(규칙·사유 머리)으로 남긴다.
2. 다른 작성자가 **원문만 보고** `scenarios.json` 을 쓴다.
3. `python -m checklist.verify_tree <slug> --dump N` → 판정이 갈린 날을 심판이 원문과 대조해 `tree_review.json` 에 남긴다.
4. `python -m checklist.verify_tree <slug> --adopt` (+ `--adopt-exits`) → `tree.json`. 검사기가 통과해야 발행된다.
