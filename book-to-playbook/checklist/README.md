# 구간② 체크리스트 만들기 — 진행 절차 (진행자용)

플레이북 → 체크리스트(`books/<slug>/tree.json`). 진행자는 이 문서대로 서브에이전트를 돌린다. 각 역할에게는 그 역할의
지침 문서 하나를 그대로 프롬프트로 준다 — 세부 규칙은 거기에만 있다(한 규칙은 한 문서에만).

| 역할 | 지침 문서(= 프롬프트 정본) | 산출물 |
|---|---|---|
| 추출자 a·b | `EXTRACTOR.md` (+ 트리 문법 `COND_DSL.md`) | `tree_candidates/<a|b>.rules.json`, `<a|b>.json` |
| 사례 작성자 | `SCENARIO.md` | `scenarios.json` |
| 심판 | `JUDGE.md` (+ `COND_DSL.md`) | `tree.json`(트리 + `review`) |

## 절차

```
① 추출자 a·b(서브에이전트 둘, 서로 모름) — 프롬프트 = EXTRACTOR.md 전문 + 입력 경로(플레이북 · source_index · COND_DSL)
② 사례 작성자(서브에이전트) — 프롬프트 = SCENARIO.md 전문 + 원문 경로 · source_index        (①과 동시에 돌려도 된다)
③ 심판(서브에이전트) — ①② 가 끝난 뒤. 프롬프트 = JUDGE.md 전문 + 입력 경로. 최종 tree.json 을 쓰고
   python -m checklist.verify_tree <slug> 정지 0 까지 반복
```

## 원칙

- **최종 트리는 심판만 쓴다.** 코드는 비교(`--dump`)와 채점(`verify_tree`)만 한다 — 트리를 만들거나 고치지 않는다.
- **책 데이터는 손으로 고치지 않는다.** 후보·사례·최종 트리를 진행자가 직접 고치지 않는다. 문제가 있으면 역할 문서·공통
  코드를 고친 뒤 그 역할을 다시 돌린다.
- **독립성**: 추출·사례·심판은 서로 다른 서브에이전트가 한다(독립성이 검증의 근거다). 추출자에게는 상대 후보·최종 트리·
  사례를, 사례 작성자에게는 트리를 보지 못하게 한다(각 역할 문서에도 적혀 있다).
- **트리 읽기는 출입구 하나**: `tree.json` 의 키 배치를 아는 코드는 `tree_gateway.py`(TreeGateway)뿐이다 — 판정·백테스트·
  검사기는 거기에 묻는다(직접 접근은 `verify_teams` 규칙 6 이 막는다). 트리 형식을 바꾸면 그 파일과 문법(`shared/cond.py`)만 고친다.
- **기록**: 실행할 때 준 입력(지침 문서 판본·입력 파일)을 남긴다 — 결과가 나쁠 때 무엇을 받았는지 되짚을 수 있게.

## 실패했을 때

- 트리 채점(`verify_tree`)의 정지는 심판이 `JUDGE.md` 5절대로 고친다.
- 심판이 "a·b 어디에도 고칠 재료가 없다"(미해결)고 보고하면 → `EXTRACTOR.md` 를 고치고 ①부터 다시.
- 사례가 원문을 잘못 읽은 것이 반복되면 → `SCENARIO.md` 를 고치고 ②를 다시.

## 판례 (관례 승격)

심판이 **판례**(원문이 안 정한 갈림을 관례로 정한 것 — `review.precedents`)를 보고하면 → **사용자 승인 후** 그 관례를
해당 지침(`EXTRACTOR.md`/`COND_DSL.md`)에 올린다. 그 뒤 모든 책이 그 관례를 따른다(다음부터 a·b 가 그 지점에서 안 갈린다).
승격 전까지는 그 책의 심판 결정으로만 남는다.
