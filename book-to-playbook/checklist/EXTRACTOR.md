# 추출자 지침 (구간② ①)

추출자 a·b 에게 그대로 주는 정본 지침이다. 추출자는 이 문서와 트리 문법 `COND_DSL.md` 만 읽는다.

## 1. 역할과 목적

트레이딩 책의 비정형 매매 지침을 판정·백테스트용 **조건식**으로 옮긴다. 결과는 **원문 근거가 한 줄씩 드러나고,
같은 원문이면 누가 써도 같은 식**이어야 한다.

보는 그 순간 상품마다 여섯 칸을 판정하는 근거가 된다 — filter(들어갈 시장) · avoid(사면 안 될 자리) ·
entry(살 자리) · caution(줄여 살까) · sizing(얼마나·나눠서) · exit(언제 얼마나 파나).

**이해 — 이 책대로 매매하려는 트레이더의 눈으로 읽는다.** 시장 용어는 통상 뜻. 트레이더 상식은 뜻을 이해하는
데만 쓰고, 저자가 안 준 기준 숫자를 채우는 데는 쓰지 않는다(4.1절).

**창작도 누락도 금지** — 원문에 없는 조건·숫자·대상을 더하지 않고(창작), 원문의 판단 문장을 빠뜨리지도 않는다
(누락). 못 옮긴 것은 사유와 함께 `unexpressed` 로 남긴다. 각 항목은 원문 판단 단위 하나에 1:1 로 대응한다.

검사기 통과는 최소 조건일 뿐 — 검사를 피하려고 식·이름을 바꾸지 않는다.

## 2. 형식·파일

### 2.1 입력과 산출물

- 입력: 플레이북 `#src`(**충실 전사본** — 저자 문장 그대로, 소절마다 `### x-y.` 제목) · `books/<slug>/source_index.json`(ref 키) · `COND_DSL.md` · 이 문서.
  상대 추출자의 결과·최종 트리·사례·`logs/`·git 기록·원문은 보지 않는다.
- 산출물 두 개(`books/<slug>/tree_candidates/`):
  1. **규칙 목록** `<a|b>.rules.json` — 행동 → 판정 → 부품의 상하위 구조와 원문 근거(2.2절). 먼저 쓴다.
  2. **트리** `<a|b>.json` — 규칙 목록을 COND_DSL 문법으로 옮긴 것(2.3절). 규칙 목록과 1:1.
- 둘 다 쓴 뒤 `python -m shared.cond fmt <파일>`(COND_DSL 5절).

### 2.2 규칙 목록 형식 (`<a|b>.rules.json`)

```json
{
  "source": {"book": "<slug>", "extractor": "a", "sections_read": ["1-1", "..."]},
  "items": [
    {"id": "A01", "kind": "행동", "zone": "avoid", "products": ["TQQQ", "SOXL", "UPRO"],
     "name": "추격 매수 금지 날", "structure": "any", "children": ["P01"],
     "source_text": ["VIX가 전일 대비 10% 이상 뛰면 추격 매수 중지"], "ref": ["2-4"]},
    {"id": "J01", "kind": "판정", "name": "장전 점수 3점 이상", "structure": "atleast 3",
     "children": ["P01", "P02", "P03", "P04", "P05"], "source_text": ["..."], "ref": ["2-6"]},
    {"id": "P01", "kind": "부품", "name": "VIX 전일 대비 10% 이상",
     "key": "VIX 전일 대비 변화율 / 이상 / 10",
     "expr": {"ge": [{"pct": [{"px": "close", "sym": "^VIX"}, 1]}, 10]},
     "interpretation": "'VIX가 튄다' = 전일 종가 대비 변화율, 저자 기준 10%",
     "source_text": ["VIX가 전일 대비 10% 이상 뛰면 추격 매수 중지", "..."], "ref": ["2-4", "2-6", "6-2"]}
  ],
  "unexpressed": [{"source_text": "...", "ref": "1-2", "reason": "저자 미명시: 판정 결과를 어느 행동에 쓰는지 말하지 않음"}]
}
```

| 필드 | 뜻 |
|---|---|
| `id` | 목록 안 고유 번호 |
| `kind` | `행동`(칸 하나를 정하는 맨 위) · `판정`(부품·판정을 묶은 판단) · `부품`(하나의 측정) |
| `zone` | 행동만: filter·avoid·entry·caution·sizing·exit |
| `products` | 행동만: 적용 상품. 판정·부품은 상품을 적지 않는다(상품 공통 — `$index`·상품 자신으로 쓴다) |
| `name` | 화면에 보일 이름(4.2절) |
| `structure` | 행동·판정만: `all` · `any` · `atleast N` · `not` — 원문 구조 그대로 |
| `children` | 행동·판정만: 하위 항목 id. **한 항목이 여러 부모의 children 에 들어갈 수 있다(그게 공유다)** |
| `key` | 부품만: "무엇을 재나 / 방향 / 기준" — 같은 key 는 같은 부품 |
| `expr` | 부품만: COND_DSL 식. 숫자가 없으면 그 자리 `"?"` |
| `interpretation` | 정성 표현을 어떻게 수치로 옮겼나(예: "'거래량이 터짐' = 거래량 ÷ 20일 평균, 배수 미명시 → ?") |
| `source_text` | 그 항목의 근거가 된 **저자 문장**(전사본) **그대로**(여러 소절이면 여럿) |
| `ref` | 그 문장들의 소절 키(문자열, 여럿이면 `·` 로 잇는다 — 형식은 문법이 정하고 코드가 강제한다) |
| `params` | 행동 칸의 규칙 값: caution `{"scale": 숫자|null}` · exit `{"sell": ...}` · sizing `{"weight": ..., "frac": ...}`(4.3절) |
| `note` | 운영 판단만(예: "'장비주'를 AMAT 로 둠 — 운영 판단"). 추천 숫자는 쓰지 않는다 |

### 2.3 트리로 옮기기 (`<a|b>.json`, COND_DSL 5절 형식)

- 상품마다 여섯 칸 전부. 칸 = 그 상품이 `products` 에 든 행동 항목들(같은 칸에 행동이 여럿이면 원문 구조로 묶는다 —
  filter·entry 는 보통 `all`/`any`, avoid 는 `any`).
- 트리에서 **두 곳 이상에 나타나는** 항목(판정·부품) → `defs` 에 한 번(본문에 `label` = name, `ref`), 쓰는 곳은 `{"def": id}` —
  **참조 자리에 `label` 을 다시 달지 않는다.** 부모가 하나여도 그 부모가 여러 상품의 칸에 들어가면(행동의 `products` 가
  둘 이상) 그 아래 항목은 상품 수만큼 나타나므로 `defs` 로 간다. 딱 한 곳에만 나타나는 항목 → 그 자리에 직접(`label`·`ref`).
- caution·exit·sizing 은 행동 항목의 `params` 로 규칙을 만들고, 규칙의 `when` 이 children 이다.
- 포지션 값(`pos`)을 쓰는 항목은 def 에 둘 수 없다 — 매도·분할 규칙 안에 직접.
- `unexpressed` 는 규칙 목록의 것을 그대로(`rule` = source_text, `ref`, `reason`). `source.extractor` = "a"/"b". `review` 는 쓰지 않는다.

## 3. 작업 단계

1. **전체를 읽는다.** 전사본 전 소절을 끝까지 읽기 전에는 아무것도 쓰지 않는다 — 같은 규칙이 여러 소절에 흩어져 있다.
2. **판단 문장을 짚는다.** 전사본은 이미 저자의 판단 문장만 담고 있다(배경·심리·일화·설명 노이즈는 구간① 전사에서
   걸러졌다) — 각 문장의 '조건 → 행동'을 짚는다(행동 = 쉰다 · 사지 않는다/미룬다 · 산다 · 줄인다/소액 · 비중·분할 · 판다).
   - **판단 문장은 앞뒤 문단과 같이 읽는다** — 조건이 한 문단에, 그 행동이 다음 문단에 나올 수 있다("힘 받는 장이다"
     다음 문단에 "흔적을 보고 들어가라" → entry). 한 문장만 보고 섣불리 `unexpressed` 로 버리지 않는다.
   - 앞뒤를 다 읽어도 행동이 없는 판정·식으로 쓸 수 없는 것은 `unexpressed`(사유 머리 COND_DSL 2절).
3. **칸을 정한다 — 원문 표현이 정한다.** "~이면 쉬어라/관망" → filter · "~이면 사지 마라/미뤄라" → avoid ·
   "~이면 사라/들어갈 만하다" → entry · "~이면 줄여서/소액만" → caution(**사되 줄이는** 말일 때만 — "사지 마라"는
   avoid) · "비중·분할" → sizing · "~이면 팔아라/축소" → exit. 한 문장에 행동이 둘이면 칸도 둘이다.
   - **조건 하나 → 행동 하나 → 칸 하나.**
   - 같은 조건에 저자가 행동의 **범위**를 말하면("쉬거나 아주 작게만") 가장 보수적인 하나로 칸을 정하고
     (filter > avoid > caution > entry) 나머지는 `note` 에 적는다.
4. **정성 표현을 수치로 해석한다.** "강하게 돌파", "거래량이 터짐", "너무 벌어짐" → 무엇을 재고 어느 방향인지.
   수동 조건이라도 수치로 판정하는 것이면 식으로 쓴다(4.1절 맨 앞). 해석은 `interpretation` 에 적는다.
5. **상하위를 위에서 아래로 그린다 — 가장 중요한 단계.**
   - 칸마다 행동 → 그 행동을 정하는 판정들 → 판정을 이루는 부품들.
   - 판정: 점수표("5지표 중 3점"), 모드(공격/균형/방어), 국면(폭락 후 재진입), 패턴("진입 위치 ①②③", "3문장 중 2개").
     원문 구조 그대로: "셋 중 하나" = any · "모두" = all · "넷 중 둘 이상" = atleast · "필수" = all 의 한 칸.
   - **같은 key 의 부품은 하나뿐이다.** 소절·표현("추격 금지", "VIX가 튐", "변동성 급등")이 달라도 key 가 같으면 같은 항목에
     `source_text`·`ref` 만 더한다. 같은 판정도 마찬가지. **다른 소절에서 저자가 그 측정의 숫자를 줬으면 `"?"` 를 그
     숫자로 채우고 `ref` 는 둘 다 단다**(한 소절은 모호, 다른 소절은 수치 — 같은 측정이면 수치가 이긴다).
   - 한 항목이 여러 부모에 쓰이면 그 부모들의 `children` 에 같은 id 를 넣는다(복사하지 않는다).
   - **상품 여럿이 같이 보는 판단(시장 점수·재진입 국면·모드 등)은 한 판정이다** — 상품마다 따로 쓰면 TQQQ 는
     공격형, UPRO 는 방어형처럼 어긋난다. (모드별 비중은 각 상품 `sizing.weight` 의 `case` 로 고른다.)
   - 상품마다 같은 모양의 판정("나스닥 20일선 위"(TQQQ) · "S&P500 20일선 위"(UPRO))은 **한 판정**이다(`$index` — 실제
     지수는 트리의 상품 `index` 필드가 정한다). 원문이 특정 종목을 지목할 때만 그 티커로 갈라진다.
6. **규칙 목록을 쓴다**(2.2절) → 2.3절대로 **트리로 옮긴다** → **자기 점검**(5절) → `fmt`.

### 예시 — 세 소절에 흩어진 VIX 이야기

전사본: 2-4 "VIX가 전일 대비 10% 이상 뛰면 추격 매수 중지" · 2-6 "장전 5지표(나스닥 선물·S&P 선물·VIX 안정·금리·달러)
중 3점 이상이어야 들어간다" · 6-2 "VIX가 튀면 방어형으로 비중을 줄인다". 2-4=avoid · 2-6=filter · 6-2=sizing 세 칸이
같은 부품("VIX 전일 대비 10% 이상")을 쓴다 — 세 소절을 다 읽기 전에 쓰면 같은 조건을 또 만든다.

```
[행동] avoid  "추격 매수 금지 날" ─────────────────────────┐
[행동] filter ─ [판정] "장전 점수 3점 이상"(atleast 3) ───┼─ [부품] "VIX 전일 대비 10% 이상"
[행동] sizing ─ [판정] "방어형 모드" ─────────────────────┘    key: VIX 전일 대비 변화율 / 이상 / 10
                                                                ref: 2-4 · 2-6 · 6-2
```

- 2-6 의 "VIX 안정"은 같은 측정의 반대쪽(10% 미만)이다 — 같은 부품을 `not` 으로 참조하지 새 부품을 만들지 않는다
  (저자가 다른 기준 숫자를 줬다면 key 가 달라 다른 부품이다).
- ❌ 하지 말 것(실제로 나온 실패): 2-4 에서 "VIX 10% 급등 — 추격 금지", 6-2 에서 "방어형 모드 — VIX 튐"을 **같은 식으로 두 번**
  만든 것 — 화면에 같은 조건이 두 줄로 뜨고, 수동이었다면 답이 엇갈린다.

## 4. 작성 규칙

### 4.1 숫자와 대상

**수치로 판정할 수 있으면 문장 수동이 아니라 DSL 식으로 쓴다** — 모르는 숫자 자리만 `"?"`(그 `"?"` 때문에 수동이
된다, COND_DSL 2절). 같은 식이면 두 추출자 결과가 하나로 합쳐진다.

| 원문 | ✅ 이렇게 | ❌ 이렇게 쓰지 않는다 |
|---|---|---|
| "SOXL이 5일선에서 너무 벌어지면" | `{"ge":[{"mul":[100,{"sub":[{"div":[{"px":"close","sym":"SOXL"},{"ma":[{"px":"close","sym":"SOXL"},5]}]},1]}]},"?"]}` | `{"manual":"저자 미명시: SOXL 5일선 이격 과다"}` |
| "최근 며칠 너무 많이 올랐으면" | `{"ge":[{"pct":[{"px":"close"},"?"]},"?"]}` | `{"manual":"저자 미명시: 최근 급등"}` |
| "거래량이 터지면" | `{"ge":[{"div":[{"px":"volume"},{"ma":[{"px":"volume"},"?"]}]},"?"]}` | `{"manual":"저자 미명시: 거래량 급증"}` |

- 저자가 준 숫자만 쓴다. "크게", "과하게", "많이", "근처"처럼 숫자가 없으면 그 숫자 자리 **하나만** `"?"`(기준이 없으면
  기준 자리, 기간이 없으면 기간 자리). 추천값·기본값은 어디에도 쓰지 않는다(식에도, 메모에도).
- 수치로 정할 수 있는 조건은 — 무엇을 재든(가격·거래량·변동성·이격·변화율·지표·비율·개수·기간·여러 종목 중 몇 개·
  내 포지션 수익률) — 숫자가 없어도 **식으로** 쓴다. 문장 수동 `{"manual"}` 은 식으로 쓸 수 없는 것만:
  순수 주관 `"저자 미명시: …(정성)"`(`(정성)` 없으면 검사기 정지) · `"데이터 없음: …"` · `"연산 없음: …"`.
- 원문이 재라는 **그 값**으로 쓴다 — 다른 값으로 흉내 내지 않는다(선물 일봉의 전일 등락은 '개장 전 선물 방향'이 아니다
  — 그 시점의 값으로 쓴다). 데이터가 지금 연결돼 있는지는 추출과 무관하다(식을 바꾸거나 감싸지 않는다). 그 값·연산이
  문법에 아직 없으면(투자자별 수급·공매도 잔고·등락 종목 수 등) `데이터 없음:`/`연산 없음:` — 문법을 넓힐 과제다.
- 방향(이상/이하)은 원문 말 그대로("너무 벌어짐" = ge, "충분히 붙음" = le). 방향이 식의 일부다.
- 원문 사례·인물 사례·"예를 들어"·금액 예시의 숫자는 — **대응하는 규칙 문장이 따로 있으면** 규칙이 아니다(규칙
  문장의 숫자를 쓴다). 그러나 **대응 규칙 없이 사례만 있으면** 저자가 그 사례로 매매 기준을 알려준 것이다 —
  트레이더의 눈으로 핵심을 규칙으로 옮기되, 그 값은 사례에서 나온 것이므로 `note` 에 "사례 유추: …"라고 적어
  규칙 문장의 숫자와 구분한다.
- 저자가 대상을 특정하지 않아 구현상 골라야 하는 것(예: "장비주" → AMAT)은 쓰되 `note` 에 "운영 판단"이라 적는다.
- 금액 축소 폭(`scale`)·비중(`weight`)·분할 비율(`frac`)도 같다 — 저자가 안 줬으면 `null`(분할은 전부 null).

### 4.2 이름

- 부품 이름 = "대상 + 상태"를 원문 용어로 짧게("기준지수 20일선 위", "VIX 전일 대비 10% 이상"). **행동·문맥 단어
  ("추격 금지", "매수", "방어형")는 넣지 않는다** — 그것은 부모(판정·행동) 이름에 붙인다.
- 판정·행동 이름 = 원문이 그 판단을 부르는 말("장전 점수 3점 이상", "방어형 모드", "진입 위치 ② 전고점 돌파 후 버팀").
- 상품 공통 항목의 이름에는 특정 상품·지수 이름을 넣지 않는다("기준지수 …", "상품 …").
- **한 식 = 한 이름, 한 이름 = 한 식.** 모든 수동 잎(`"?"` 식·문장)은 `label`·`ref` 필수.

### 4.3 조심·비중·매도 (형식은 COND_DSL 4절)

- **caution**: 사되 줄이는 말만. 폭을 안 줬으면 `"scale": null`.
- **sizing**: 비중은 저자가 준 %. **저자 본인의 배분·기준은 규칙이다 — 저자가 자기 배분을 금액으로 줬으면 %로 환산해
  쓴다(계산이다).** "예를 들어" 가정으로 든 예시 숫자만 규칙이 아니다. 분할 비율을 안 줬으면 차수마다 `"frac": null`
  (지어내지 않는다). 2차 이후 `when` 에서는 포지션 값을 쓴다.
- **exit**:
  - "판다·축소·정리"라는 말이 있어야 매도 규칙이다. "재판단", "검문", "판단한다"처럼 판다는 말이 없으면 옮기지 않는다.
  - "축소"인데 비율이 없으면 비율 자리만 `null` 로 두고 매도 규칙으로 쓴다(`{"remaining": null}` — 구조는 살린다).
  - 저자가 구간("7~10%")으로 말하면 그 구간에 **처음 닿는** 하한(7)으로 쓰고 `note` 에 적는다.
  - 포지션 값(`pos`)과 시장 조건(20일선 이탈 등)을 그대로 섞어 쓴다.
  - 계좌 전체 기준(계좌 −5%, 현금 비중 등)·실적 발표일·뉴스는 상품 하나로 계산할 수 없다 — 문장 수동 또는 `unexpressed`.
  - 안전장치를 끼우지 않는다 — 저자가 안 준 손절·기간만료를 만들지 않는다.

## 5. 자기 점검 (제출 전)

- [ ] 전사본의 모든 판단 문장이 규칙 목록의 `source_text` 또는 `unexpressed` 에 있다.
- [ ] 같은 key 의 부품이 둘이 아니다 · 부품 이름에 행동·문맥 단어가 없다 · 상품마다 복사한 판정이 없다.
- [ ] 원문에 없는 숫자·조건·대상이 없다(운영 판단은 `note`) · 추천 숫자가 어디에도 없다.
- [ ] 트리의 노드와 규칙 목록의 항목이 1:1 이다(이름·식이 같다).
- [ ] 트리: `cond.validate_tree` 통과 · 같은 식 두 벌 없음 · 한 식 한 이름 · 두 파일 모두 `fmt` 적용.
