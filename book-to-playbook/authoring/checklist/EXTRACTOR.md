# 추출자 지침 (구간② ①)

추출자 a·b 에게 그대로 주는 정본 지침이다. 추출자는 이 문서와 트리 문법 `COND_DSL.md` 만 읽는다.

## 1. 역할과 목적

트레이딩 책의 비정형 매매 지침을 판정·백테스트용 **규칙**으로 옮긴다. 결과는 **원문 근거가 한 줄씩 드러나고,
같은 원문이면 누가 써도 같은 식**이어야 하며, 보는 순간 상품마다 **살지·팔지·안 살지**를 판정하는 근거가 된다.
상품 × 칸 격자는 없다 — `COND_DSL.md` 1절 규칙 모양으로 옮긴다(행동 동사 셋: **안 산다 · 산다 · 판다**).

**트레이더의 눈으로 읽는다 — 식이 아니라 행동으로(지배 원칙).** 저자가 **무엇을 하라는지(행동)**를 먼저 잡고,
식은 그 행동을 재는 도구로 본다. 저자는 매매법을 **구조로 세워** 가르친다 — 그 구조(여러 신호를 모은 **게이트**,
단계로 잇는 **사다리**; §4 1단계)를 평면으로 흩뜨리지 말고 **입체로 잡는다.** 기계처럼 식만 맞추면 ① 흩어진 한
매매법을 못 모으고 ② 같은 지시의 반복을 못 걸러낸다. 쓸지·합칠지의 기준은 늘 "**이 규칙이 트레이더의 행동을 바꾸는
날이 있나**". 시장 용어는 통상 뜻으로 이해하되, 저자가 안 준 숫자를 트레이더 상식으로 채우지 않는다(§2).


## 2. 네 가지 원칙 (`COND_DSL.md` 0절과 같다 — 추출의 심장)

1. **충실성 — 표현 가능한 식은 반드시 추출한다.** 가격·거래량·변동성·이격·변화율·지표·비율·개수·기간·여러 종목
   중 몇 개·내 포지션 수익률 — 무엇을 재든, 숫자가 없어도 **식으로** 쓴다. `skip` 은 식으로 **못 쓰는 진짜 잔여**
   (`데이터 없음:`·`연산 없음:`)에만. 저자가 **측정만 주고 행동을 안 준** 것은 skip 이 아니라 **이름 조건(`cond`)**.
   한 문장에 식 되는 조각과 안 되는 조각이 섞이면 **쪼갠다**.
2. **상대 크기는 입장(`do`·등급)이지 `qty` 가 아니다.** "아주 작게·소액만·크게·확대·축소·줄여라"처럼 숫자 없는
   크기 말은 금액이 아니라 사라/사지 마라는 판정이다 → `do` 동사로. 가장 보수적인 쪽으로 정하고 `note` 에 원문을
   적는다("20일선 아래 쉬거나 아주 작게"→`안 산다`, `note`: "원문 '쉬거나 아주 작게'"). `qty` 에 `"?"` 를 박지 않는다.
3. **모르면 `"?"`.** 조건은 되는데 **숫자만** 저자가 안 줬으면 그 숫자 자리 하나만 `"?"`. 추천값·기본값·지어낸
   숫자는 어디에도 쓰지 않는다. 행동(판다)은 분명한데 비율만 미명시면 `qty.x: "?"`.
4. **한 식 = 한 이름.** 같은 측정은 이름 하나로 두고, 다른 규칙은 `{"rule": "이름"}` 으로 참조한다(복제 금지).
   단 **저자가 같은 측정에 기준 숫자를 달리 줬으면 그건 다른 규칙**이다(둘 다 두고 `note` — `COND_DSL.md` 0절 5).
   **모든 수동 잎(`"?"` 식·문장 수동)은 반드시 `label`(+ `ref`)을 단다** — 사람이 그 조건을 볼 때 "무엇을 확인하는지"
   (측정 대상·방향)를 알아야 하기 때문. 이름 없는 수동 잎은 화면에 "수동 확인"만 떠서 쓸모가 없다. 자주 쓰는 측정이면
   이름 조건(`cond`)으로 빼서 `{"rule"}` 참조, 한 곳에만 쓰면 그 자리에 `label`·`ref` 직접.

**창작은 절대 금지 · 누락도 금지.** 원문에 없는 신호·대상·임계·숫자는 **어느 것도** 지어내지 않고(창작), 원문의
판단 문장을 빠뜨리지도 않는다(누락). 단 **저자가 이미 세운 구조를 잇는 것**(흩어진 입력을 한 결정으로 묶기·단계를
사다리로 잇기, §4)은 창작이 아니라 **충실**이다 — 구조는 저자 것이고 추출자는 **드러낼** 뿐, 없는 걸 만들지 않는다.
저자가 안 준 숫자는 그대로 `"?"`. 검사기 통과는 최소 조건일 뿐 — 검사를 피하려고 식·이름을 바꾸지 않는다.

## 3. 입력과 산출물

- 입력: 플레이북 `#src`(**충실 전사본** — 저자 문장 그대로, 소절마다 `### x-y.` 제목) · `books/<slug>/source_index.json`
  (ref 키) · `COND_DSL.md` · 이 문서. 상대 추출자의 결과·최종 트리·사례·`logs/`·git 기록·원문은 보지 않는다.
- 산출물 둘(`books/<slug>/tree_candidates/`, 둘 다 v3):
  1. **규칙 목록** `<a|b>.rules.json` — 원문 판단 → 규칙의 상하위를 사람이 읽게 적은 것(3.1절). 먼저 쓴다.
  2. **트리** `<a|b>.json` — 규칙 목록을 `COND_DSL.md` 1·5절 문법으로 옮긴 것. 규칙 목록과 1:1.
- 둘 다 쓴 뒤 `python -m dsl.tradeTool fmt <파일>`(`COND_DSL.md` 5절).

### 3.1 규칙 목록 형식 (`<a|b>.rules.json`)

규칙 목록은 각 원문 판단이 어느 규칙이 됐는지, 어떤 측정을 공유하는지를 사람이 짚을 수 있게 적는다.

```json
{
  "book": "<slug>",
  "items": [
    {"label": "VIX 전일 대비", "ref": ["2-4", "6-2"],
     "value": {"pct": [{"px": "close", "sym": "^VIX"}, 1]},
     "then": [{"when": {"ge": ["$value", 20]}, "do": "판다", "qty": {"of": "held", "x": "?"}},
              {"when": {"ge": ["$value", 10]}, "do": "안 산다"}],
     "source_text": ["VIX가 전일 대비 10% 이상 뛰면 추격 매수 중지", "..."],
     "note": "'VIX가 튄다' = 전일 종가 대비 변화율, 저자 기준 10%·20%"},

    {"label": "장전 점수", "ref": ["2-6"],
     "value": {"atleast": "...", "of": ["..."]},
     "then": [{"when": {"ge": ["$value", 4]}, "do": "산다"},
              {"when": {"le": ["$value", 2]}, "do": "안 산다"}],
     "source_text": ["장전 5지표 중 ..."]},

    {"label": "계좌 −5% 축소", "ref": ["8-3"],
     "skip": "연산 없음: 계좌 전체 기준",
     "source_text": ["원금 대비 −5%면 계좌를 줄인다"]}
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `label` | 조건의 이름(대상 + 상태, 행동 단어 없음). 책 안에서 유일. 다른 규칙이 이 이름으로 부른다 |
| `ref` | 근거 소절 키(여럿이면 배열 또는 `·`) |
| `value` / `then` / `skip` | 트리와 같은 모양(`COND_DSL.md` 1절) — 행동 규칙은 `then`, 이름 조건은 둘 다 없음, 못 옮긴 건 `skip` |
| `on` | 원문이 이름으로 지목한 상품(생략 = 전부) |
| `source_text` | 그 규칙의 근거가 된 **저자 문장(전사본) 그대로**(여러 소절이면 여럿) |
| `note` | 해석(정성 표현을 어떻게 수치로 옮겼나) · 운영 판단 · 보수적으로 고른 입장의 원문 — 추천 숫자는 쓰지 않는다 |

규칙 목록과 트리는 1:1 이다 — 같은 `label`·같은 식. 트리에는 `source_text` 대신 `ref`·`note` 만 남는다.

## 4. 작업 단계

**합치고 쪼개는 단 하나의 기준.** 규칙 하나 = 저자가 내리는 **서로 다른 행동 결정** 하나다 — 문장·소절·신호·상품 수가
아니다. 문장을 규칙으로 옮기지 말고 저자의 **의사결정 모델**(언제 사고·팔고·쉬는가)을 복원해 거기에 문장을 붙인다.
합칠지 쪼갤지는 늘 하나로 묻는다 — **"이 둘이 트레이더에게 다른 날 다른 행동을 시키는가?"** 아니면 한 규칙, 맞으면 두
규칙. 책이 한 결정을 아무리 흩어 놓아도 이 테스트로 되돌린다:

| 책이 이렇게 흩어 놓아도 | 테스트가 보는 것 | → 결과 |
|---|---|---|
| 여러 신호로 한 판단("점수 N점↑", "N개 중 M개") | 신호 하나는 독립 행동 아님 | **한 규칙** `atleast`/`any`/`all` (게이트) |
| 단계로 나눠 말함(분할·익절 1·2·3차) | 단계는 한 프로그램의 진행 | **한 사다리** `pos:filled`/임계 단계 |
| 여러 소절이 한 결정을 나눠 설명 | 설명은 새 행동 아님 | **한 규칙** (재료는 `{"rule"}` 참조 · 설명만 하는 소절은 규칙 아님) |
| 임계가 포개진 같은 `do`("≥20" ⊂ "≥10") | 삼켜지는 쪽은 '다른 날'이 없음 | **한 규칙** (느슨한 쪽, 뉘앙스 `note`) |
| 공통인데 **한 상품만** 조건이 더 붙음 | 기반은 모두 같은 결정 | **공통 규칙 그대로**(`on` 안 붙임) **+ 그 상품 델타만** `on:[상품]` |
| `do` 가 다름(사지 마 ↔ 팔아 ↔ 재진입) | 다른 행동 | **다른 규칙** |

지어내지 않는다(§2) — 묶고 잇는 건 저자 구조를 **드러내는** 것이고, 저자가 안 준 임계·신호는 채우지 않는다(`"?"`).

1. **전체를 읽고 구조를 그린다.** 전 소절을 끝까지 읽기 전엔 아무것도 쓰지 않는다(한 결정이 여러 소절에 흩어지고 한 측정을
   여러 소절이 공유한다). 읽으면서 저자가 세운 구조 — 게이트·사다리·독립 — 를 위 테스트로 먼저 가른다. 저자가 점수표·단계표를
   **명시 안 했어도** 소절들이 한 결정이면 결합을 **추출자가 구성한다**(장 제목·"이 중 하나"·"먼저…다음"이 근거). 억지로 묶진 않는다.
2. **결정을 규칙으로 쓴다.** 무엇을 하라(사라/사지 마라/팔아라) — 행동 셋 **안 산다 · 산다 · 판다** — 를 잡고, 그 결정의
   신호들을 한 규칙의 `when`(`any`/`atleast`/`all`)으로 묶는다(신호마다 규칙을 만들지 않는다). 동사는 원문이 정한다.
   **크기 말은 입장으로**(원칙 2): "아주 작게"→`안 산다`, "소액만"→관망 — `qty` 로 뭉개지 않는다.
3. **정성 표현을 식으로.** "강하게 돌파"·"거래량 터짐"·"너무 벌어짐" → 무엇을 어느 방향으로 재는지. 숫자 없어도 **식으로**,
   모르는 숫자 자리만 `"?"`(원칙 1·3). 해석은 `note` 에 적는다.
4. **같은 측정 = 이름 하나.** 소절·표현이 달라도 같은 측정이면 이름 조건 하나로 두고 다른 규칙은 `{"rule": "이름"}` 참조
   (복제 금지). **같은 모양이면 `$index` 로 하나**("나스닥 20일선 위"·"S&P500 20일선 위" → 한 규칙, 실제 지수는 상품의
   `index`; 원문이 종목을 지목할 때만 `on`). 저자가 기준 숫자를 달리 줬으면 별개 규칙(`COND_DSL.md` 0절 5). 저자가
   **측정만 주고 행동을 안 줬으면 이름 조건(`cond`)** — skip 아님.
5. **얼마나·분할·매도.** 저자가 준 비율만 `qty: {of, x}`(`COND_DSL.md` 1절). "1차 다음 2차"는
   `{"pos": "filled", "rule": "1차 이름"}`. "판다·축소·정리"라는 말이 있어야 판다 규칙이다(판다는 말 없으면 옮기지 않음).
   축소인데 비율 없으면 `qty.x: "?"`, 구간("7~10%")은 하한(7)+`note`. 안전장치(저자가 안 준 손절)는 만들지 않는다.
   **못 옮긴 것만 `skip`** — 상품 하나로 계산 못 하면 `"연산 없음: …"`, 수집할 값 없으면 `"데이터 없음: …"`. 식 되는데 skip 금지(원칙 1).
6. **규칙 목록**(3.1절) → **트리** → **자기 점검**(5절) → `fmt`.

### 예시 — 저자의 구조를 세운다 (게이트 · 사다리 · 중복 접기)

**게이트 (ch2 매수 전 신호).** 저자가 2-6 에서 "장전 5지표 점수 4점↑ 공격"이라 점수표를 줬다 → 5신호를
`{"atleast": 4, "of": [...]}` **한 규칙**, 각 신호는 이름 조건으로 빼 `{"rule"}` 참조. 저자가 점수표를 **안 주고**
2-1~2-5 에 신호만 흩어놨어도, 장 제목("매수 전 반드시 보는 신호")이 "함께 보는 가부 판단"이라 말하면 **같은 게이트를
추출자가 구성한다** — 임계 N 은 저자가 주면 숫자, 없으면 `atleast "?"`(사람이 개수 판단). 신호·임계를 **지어내진 않는다**.

**사다리 (ch7 익절).** "7~10%서 1차, 15~20%서 2차"는 흩어진 두 규칙이 아니라 **한 익절 프로그램의 두 단** → 수익률
임계로 이은 단계(1차 `ret≥0.07` 30% · 2차 `ret≥0.15` 30%)로 **잇는다**, 따로 떼지 않는다.

**중복은 접는다 (VIX).** 측정은 하나("VIX 전일 대비"), 임계·방향으로 행동만 갈린다. "≥10 → 사지 마"가 "≥20+갭 → 사지 마"·
"세 방향 압력"을 발동에서 **삼키면**(둘 다 VIX≥10 포함) **한 규칙**으로 접고 뉘앙스는 `note`. 단 **`do` 가 다른**
"≥20 → 비중 축소"(판다)·"꺾임 → 재진입"(산다)은 임계가 포개져도 남긴다.

❌ 소절마다 규칙 쪼개기 · 측정식을 규칙마다 두 번 쓰기(`"?"` 면 답이 엇갈린다) · 저자가 안 준 임계·신호 채우기.

## 5. 자기 점검 (제출 전)

- [ ] 전사본의 모든 판단 문장이 어떤 규칙의 `source_text` 또는 `skip` 규칙에 있다(누락 0).
- [ ] **한 결정 = 한 규칙 · 구조를 세웠다**(§4 테스트·표) — 신호마다 쪼개지 않고 게이트/사다리로 묶었다. 저자가 점수표·단계표를 안 줬어도 소절들이 한 결정이면 결합을 **구성**했다(임계는 주면 숫자·없으면 `"?"`). 쪼갠 건 행동(`do`)이 다를 때뿐이다.
- [ ] **행동 바꾸는 날 없는 규칙이 없다**(§4 테스트·표) — 같은 `do` 인데 발동이 다른 규칙에 늘 포함되는(VIX ≥20 ⊂ ≥10 류) 규칙을 따로 두지 않았다. `do` 가 다르면(사지 마 ↔ 팔아 ↔ 재진입) 남겼다. 공통 결정은 공통으로(`on` 안 붙임), 한 상품만 더 붙는 조건은 그 상품 델타로만.
- [ ] 식으로 쓸 수 있는데 `skip` 한 것이 없다(원칙 1) · `skip` 은 `데이터 없음:`·`연산 없음:` 뿐.
- [ ] 저자가 측정만 주고 행동을 안 준 것은 `skip` 이 아니라 이름 조건(`then`·`skip` 없음)이다.
- [ ] 크기 말("크게/소액")을 `qty: "?"` 로 박지 않았다 — `do`·등급으로 옮겼다(원칙 2).
- [ ] 같은 측정이 두 규칙에 복제되지 않았다 — `{"rule"}` 로 참조(원칙 4). 단 기준 숫자가 다르면 별개 규칙이다.
- [ ] 원문에 없는 숫자·조건·대상이 없다(운영 판단은 `note`) · 추천 숫자가 어디에도 없다.
- [ ] 규칙 목록과 트리가 1:1 이다(같은 `label`·같은 식) · `version` 은 3.
- [ ] 트리: 형식 검사(`TreeGateway.validate` — `dsl/tree_gateway.py`) 통과 · 같은 식 두 벌 없음 · 두 파일 모두 `fmt`.
