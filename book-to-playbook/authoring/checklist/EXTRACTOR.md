# 추출자 지침 (구간② ①)

추출자 a·b 에게 그대로 주는 정본 지침이다. 추출자는 이 문서와 트리 문법 `COND_DSL.md` 만 읽는다.

## 1. 역할과 목적

트레이딩 책의 비정형 매매 지침을 판정·백테스트용 **규칙**으로 옮긴다. 결과는 **원문 근거가 한 줄씩 드러나고,
같은 원문이면 누가 써도 같은 식**이어야 한다. 보는 그 순간 상품마다 **살지·팔지·안 살지**를 판정하는 근거가 된다.

**원문 판단 하나 = 규칙 하나.** 상품 × 칸 6개의 격자는 없다 — `COND_DSL.md` 1절의 규칙 모양으로 옮긴다
(행동 동사 셋: **안 산다 · 산다 · 판다**).

**이해 — 이 책대로 매매하려는 트레이더의 눈으로 읽는다.** 시장 용어는 통상 뜻. 트레이더 상식은 뜻을 이해하는
데만 쓰고, 저자가 안 준 기준 숫자를 채우는 데는 쓰지 않는다.

## 2. 네 가지 원칙 (`COND_DSL.md` 0절과 같다 — 추출의 심장)

1. **충실성 — 표현 가능한 식은 반드시 추출한다.** 가격·거래량·변동성·이격·변화율·지표·비율·개수·기간·여러 종목
   중 몇 개·내 포지션 수익률 — 무엇을 재든, 숫자가 없어도 **식으로** 쓴다. `skip` 은 식으로 **못 쓰는 진짜 잔여**
   (`데이터 없음:`·`연산 없음:`)에만. 저자가 **측정만 주고 행동을 안 준** 것은 skip 이 아니라 **이름 조건(`cond`)**.
   한 문장에 식 되는 조각과 안 되는 조각이 섞이면 **쪼갠다**.
2. **상대 크기는 입장(`do`·등급)이지 `qty` 가 아니다.** "아주 작게·소액만·크게·확대·축소·줄여라"처럼 숫자 없는
   크기 말은 금액이 아니라 사라/사지 마라는 판정이다 → `do` 동사로. 가장 보수적인 쪽으로 정하고 `note` 에 원문을
   적는다("20일선 아래 쉬거나 아주 작게"→`안 산다`, `note`: "원문 '쉬거나 아주 작게'"). `qty` 에 `"?"` 를 박지 않는다.
3. **모르면 `"?"`.** 조건은 되는데 **숫자만** 저자가 안 줬으면 그 숫자 자리 하나만 `"?"`. 추천값·기본값·지어낸
   숫자는 어디에도 쓰지 않는다. 행동(판다)은 분명한데 비율만 미명시면 `qty.x: "?"`.
4. **한 식 = 한 이름.** 같은 측정은 이름 하나로 두고, 다른 규칙은 `{"rule": "이름"}` 으로 참조한다(복제 금지).
   단 **저자가 같은 측정에 기준 숫자를 달리 줬으면 그건 다른 규칙**이다(둘 다 두고 `note` — `COND_DSL.md` 0절 5).

창작도 누락도 금지 — 원문에 없는 조건·숫자·대상을 더하지 않고(창작), 원문의 판단 문장을 빠뜨리지도 않는다(누락).
검사기 통과는 최소 조건일 뿐 — 검사를 피하려고 식·이름을 바꾸지 않는다.

## 3. 입력과 산출물

- 입력: 플레이북 `#src`(**충실 전사본** — 저자 문장 그대로, 소절마다 `### x-y.` 제목) · `books/<slug>/source_index.json`
  (ref 키) · `COND_DSL.md` · 이 문서. 상대 추출자의 결과·최종 트리·사례·`logs/`·git 기록·원문은 보지 않는다.
- 산출물 둘(`books/<slug>/tree_candidates/`, 둘 다 v3):
  1. **규칙 목록** `<a|b>.rules.json` — 원문 판단 → 규칙의 상하위를 사람이 읽게 적은 것(3.1절). 먼저 쓴다.
  2. **트리** `<a|b>.json` — 규칙 목록을 `COND_DSL.md` 1·5절 문법으로 옮긴 것. 규칙 목록과 1:1.
- 둘 다 쓴 뒤 `python -m dsl.tradeTool fmt <파일>`(`COND_DSL.md` 5절).

### 3.1 규칙 목록 형식 (`<a|b>.rules.json`)

규칙 목록은 각 원문 판단이 어느 규칙이 됐는지, 어떤 측정을 공유하는지를 사람이 짚을 수 있게 적는다.

```json
{
  "book": "<slug>",
  "items": [
    {"label": "VIX 전일 대비", "ref": ["2-4", "6-2"],
     "value": {"pct": [{"px": "close", "sym": "^VIX"}, 1]},
     "then": [{"when": {"ge": ["$value", 20]}, "do": "판다", "qty": {"of": "held", "x": "?"}},
              {"when": {"ge": ["$value", 10]}, "do": "안 산다"}],
     "source_text": ["VIX가 전일 대비 10% 이상 뛰면 추격 매수 중지", "..."],
     "note": "'VIX가 튄다' = 전일 종가 대비 변화율, 저자 기준 10%·20%"},

    {"label": "장전 점수", "ref": ["2-6"],
     "value": {"atleast": "...", "of": ["..."]},
     "then": [{"when": {"ge": ["$value", 4]}, "do": "산다"},
              {"when": {"le": ["$value", 2]}, "do": "안 산다"}],
     "source_text": ["장전 5지표 중 ..."]},

    {"label": "계좌 −5% 축소", "ref": ["8-3"],
     "skip": "연산 없음: 계좌 전체 기준",
     "source_text": ["원금 대비 −5%면 계좌를 줄인다"]}
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `label` | 조건의 이름(대상 + 상태, 행동 단어 없음). 책 안에서 유일. 다른 규칙이 이 이름으로 부른다 |
| `ref` | 근거 소절 키(여럿이면 배열 또는 `·`) |
| `value` / `then` / `skip` | 트리와 같은 모양(`COND_DSL.md` 1절) — 행동 규칙은 `then`, 이름 조건은 둘 다 없음, 못 옮긴 건 `skip` |
| `on` | 원문이 이름으로 지목한 상품(생략 = 전부) |
| `source_text` | 그 규칙의 근거가 된 **저자 문장(전사본) 그대로**(여러 소절이면 여럿) |
| `note` | 해석(정성 표현을 어떻게 수치로 옮겼나) · 운영 판단 · 보수적으로 고른 입장의 원문 — 추천 숫자는 쓰지 않는다 |

규칙 목록과 트리는 1:1 이다 — 같은 `label`·같은 식. 트리에는 `source_text` 대신 `ref`·`note` 만 남는다.

## 4. 작업 단계

1. **전체를 읽는다.** 전사본 전 소절을 끝까지 읽기 전에는 아무것도 쓰지 않는다 — 같은 규칙이 여러 소절에 흩어져 있고,
   한 측정을 여러 소절이 공유한다. 다 읽기 전에 쓰면 같은 측정을 또 만든다.
2. **판단 문장을 짚는다.** 전사본은 이미 저자의 판단 문장만 담고 있다 — 각 문장의 '조건 → 행동'을 짚는다.
   행동은 셋 중 하나다: **안 산다**(쉰다·사지 마라·미뤄라·줄여 사지 마라) · **산다**(사라·들어가라·비중·분할) ·
   **판다**(팔아라·축소·정리). 조건이 한 문단, 그 행동이 다음 문단에 올 수 있으니 **앞뒤를 같이 읽는다**.
3. **규칙으로 옮긴다 — 원문 표현이 동사를 정한다.** "~이면 쉬어라/사지 마라/줄여 사지 마라" → `안 산다` ·
   "~이면 사라/들어갈 만하다/비중" → `산다` · "~이면 팔아라/축소" → `판다`. 한 문장에 행동이 둘이면 규칙도 둘이다.
   - **크기 말은 입장으로**(원칙 2): "쉬거나 아주 작게"는 `안 산다`, "소액만"은 관망(=아무 산다 규칙도 안 걸림) —
     `qty` 로 뭉개지 않는다.
4. **정성 표현을 수치로 해석한다.** "강하게 돌파"·"거래량이 터짐"·"너무 벌어짐" → 무엇을 재고 어느 방향인지.
   숫자가 없어도 **식으로** 쓰고 모르는 숫자 자리만 `"?"`(원칙 1·3). 해석은 `note` 에 적는다.
5. **측정을 모은다 — 같은 식은 이름 하나.** 소절·표현이 달라도 같은 측정이면 규칙(또는 이름 조건) 하나로 두고
   `ref`·`source_text` 만 더한다. 다른 규칙이 그 측정을 쓰면 `{"rule": "이름"}` 으로 참조한다(복제 금지).
   - **같은 모양이면 `$index` 로 하나.** "나스닥 20일선 위"(TQQQ)·"S&P500 20일선 위"(UPRO)는 **한 규칙**이다
     (`$index` — 실제 지수는 상품의 `index` 필드). 원문이 특정 종목을 지목할 때만 그 티커로 `on` 을 쓴다.
   - **저자가 측정만 주고 행동을 안 줬으면 이름 조건(`cond`)** 으로 남긴다(`then`·`skip` 없이 `value`만). skip 아님.
   - **점수표는 `atleast`.** "5지표 중 3점" = `{"atleast": 3, "of": [...]}`. 조각이 다른 규칙과 겹치면 `{"rule"}` 참조.
6. **얼마나·분할·매도를 적는다.**
   - 저자가 준 비율만 `qty: {of, x}`(`COND_DSL.md` 1절). "1차 다음 2차"는 `{"pos": "filled", "rule": "1차 이름"}`.
   - "판다·축소·정리"라는 말이 있어야 판다 규칙이다("재판단"처럼 판다는 말이 없으면 옮기지 않는다). 축소인데 비율이
     없으면 `qty.x: "?"`. 구간("7~10%")은 처음 닿는 하한(7)으로 쓰고 `note`. 안전장치(저자가 안 준 손절)를 만들지 않는다.
   - **못 옮긴 것만 `skip`.** 계좌 전체 기준·종목 간 돈 이동·지난 매매 이력처럼 상품 하나로 계산 못 하는 것은
     `"연산 없음: …"`, 수집할 값이 없는 것은 `"데이터 없음: …"`. 식이 되는데 skip 하면 안 된다(원칙 1).
7. **규칙 목록을 쓴다**(3.1절) → **트리로 옮긴다** → **자기 점검**(5절) → `fmt`.

### 예시 — 세 소절에 흩어진 VIX 이야기

전사본: 2-4 "VIX가 전일 대비 10% 이상 뛰면 추격 매수 중지" · 2-6 "장전 5지표 중 3점 이상이어야 들어간다"(그중 하나가
VIX 안정) · 6-2 "VIX가 튀면 비중을 줄인다". 세 소절이 같은 측정("VIX 전일 대비")을 쓴다 — 다 읽기 전에 쓰면 같은
측정을 두세 번 만든다.

- VIX 전일 대비를 **이름 조건 하나**(`label`: "VIX 전일 대비", `value`: `{"pct": [{"px":"close","sym":"^VIX"},1]}`)로 두고,
  2-4("10% 이상 뛰면 안 산다")·6-2("튀면 비중 줄여 → 크기 말 → 안 산다/관망")가 `{"rule": "VIX 전일 대비"}` 로 참조.
- 2-6 의 "VIX 안정"은 같은 측정의 반대쪽(10% 미만)이다 — 같은 이름을 쓰지, 새 측정을 만들지 않는다.
- ❌ 하지 말 것: 2-4 와 6-2 에서 VIX 측정식을 **각자 두 번** 쓴 것 — 화면에 같은 조건이 두 줄로 뜨고, `"?"` 였다면 답이 엇갈린다.

## 5. 자기 점검 (제출 전)

- [ ] 전사본의 모든 판단 문장이 어떤 규칙의 `source_text` 또는 `skip` 규칙에 있다(누락 0).
- [ ] 식으로 쓸 수 있는데 `skip` 한 것이 없다(원칙 1) · `skip` 은 `데이터 없음:`·`연산 없음:` 뿐.
- [ ] 저자가 측정만 주고 행동을 안 준 것은 `skip` 이 아니라 이름 조건(`then`·`skip` 없음)이다.
- [ ] 크기 말("크게/소액")을 `qty: "?"` 로 박지 않았다 — `do`·등급으로 옮겼다(원칙 2).
- [ ] 같은 측정이 두 규칙에 복제되지 않았다 — `{"rule"}` 로 참조(원칙 4). 단 기준 숫자가 다르면 별개 규칙이다.
- [ ] 원문에 없는 숫자·조건·대상이 없다(운영 판단은 `note`) · 추천 숫자가 어디에도 없다.
- [ ] 규칙 목록과 트리가 1:1 이다(같은 `label`·같은 식) · `version` 은 3.
- [ ] 트리: 형식 검사(`TreeGateway.validate` — `dsl/tree_gateway.py`) 통과 · 같은 식 두 벌 없음 · 두 파일 모두 `fmt`.
