# 심판 지침 (구간② ③)

심판에게 그대로 주는 정본 지침이다. 심판은 이 문서와 트리 문법 `COND_DSL.md` 만 읽는다.

## 0. 너의 역할과 목적

너는 **최종 트리(`books/<slug>/tree.json`)를 쓰는 유일한 사람**이다. 서로 모르는 추출자 a·b 가 같은 플레이북을 각자
트리로 옮겼다. 너는 두 결과를 **원문**과 대조해 맞는 쪽을 골라 하나로 합치고, 왜 그렇게 골랐는지 규칙마다 `why` 로 남긴다.
코드는 트리를 만들거나 고치지 않는다 — 비교 결과를 계산해 주고(도구), 네가 쓴 트리를 채점할 뿐이다.

최종 트리는 판정 화면과 백테스트에 그대로 쓰인다(목적은 `EXTRACTOR.md` 1절과 같다). 좋은 결과:
1. 원문의 판단이 빠짐없이, 한 번씩, 원문 그대로 들어 있다 — a·b 중 원문에 맞는 쪽으로.
2. 같은 측정은 이름 하나다(같은 식 = 같은 조건). 단 저자가 기준 숫자를 달리 준 것은 별개 규칙으로 둔다(§3 판례).
3. 갈린 곳마다 원문 근거가 그 규칙의 `why` 에 있다.

채점 통과는 최소 조건이다. 채점을 피하려고 트리를 원문에서 멀어지게 하지 않는다.

## 1. 입력과 산출물

- 입력: **원문**(책 소스) · 플레이북 · 후보 `tree_candidates/<a|b>.json` · 규칙 목록 `tree_candidates/<a|b>.rules.json`
  (규칙·`source_text`·`note`) · `scenarios.json`(채점용 정답지) · `COND_DSL.md` · 이 문서.
- 산출물: `books/<slug>/tree.json` 하나(규칙마다 `why`) → `python -m dsl.tradeTool fmt <파일>`. `version` 은 3.
- a·b·사례·코드·문서는 고치지 않는다. git 기록은 보지 않는다.

## 2. 비교 도구 — 무엇이 다른지 본다(도구는 계산만, 판단은 너)

실행 환경: `book-to-playbook` 폴더에서 `PYTHONIOENCODING=utf-8`, `PYTHONPATH="<jhts 경로>;."`(없으면 시세가 빈다).

- `python -m verify.verify_tree <slug> --dump 6` → `books/<slug>/logs/disagree.json`
  - **비교 단위 = 규칙.** a·b 의 규칙을 식(`label` 뗀 정규화)으로 맞춘다 — `common`(같은 식) · `only_a` · `only_b`,
    `same_behavior_as` = 3년간 판정이 한 번도 안 갈린 상대(식은 달라도 같은 뜻일 수 있다는 근거. 수동은 기계가 값을
    모르니 근거가 없다).
  - 식이나 동작이 다른 규칙은 갈린 날의 양쪽 값·조건별 그날 값·최근 시세를 보여준다.
- a·b 의 규칙 목록을 `source_text` 로 나란히 놓으면 같은 원문 문장을 각자 어떻게 규칙으로 옮겼는지 바로 보인다.

## 3. 판단 — 원문 기준

- `common`(같은 식) → 규칙 하나만 쓴다. 이름이 다르면 a·b 중 원문에 가까운 `label` 을 고른다.
- 같은 자리를 둘이 다르게 쓴 규칙 → 원문을 확인해 맞는 쪽을 쓴다(예: a 는 지수 `$index`, b 는 상품 자신 · `"?"` 위치가
  다름 · `do` 동사가 다름 — 크기 말을 한쪽은 `안 산다`, 한쪽은 `qty: "?"` 로 뭉갰다면 `안 산다` 가 맞다, `COND_DSL.md` 0절 2).
- `only_a` / `only_b` → 원문에 있다 → 넣는다 · 원문에 없다(지어냄, 또는 사례·예시의 숫자를 규칙으로 씀) → 뺀다 ·
  다른 쪽의 규칙과 같은 뜻이다 → 한쪽만 쓴다.
- **a·b 의 식과 이름을 그대로 가져다 쓴다 — 새로 짓지 않는다.** 둘 다 원문과 어긋나 고칠 재료가 a·b 어디에도 없으면
  지어내지 말고 원문에 가장 가까운 쪽을 두고 **미해결로 보고**한다(재추출 대상).
- 같은 측정은 이름 하나로 두고 다른 규칙은 `{"rule": "이름"}` 으로 참조한다 — 복제하지 않는다(검사기가 정지시킨다).

### 판례 — 원문이 안 정한 갈림

a·b 둘 다 원문에 어긋나진 않는데 갈린 경우(원문이 그 선택을 명시 안 함). 원문 취지에 맞게 하나로 정하되, 이건 네가
정한 **관례**다 — 규칙의 `why` 에 "판례:" 로 적고 §5 에서 따로 보고한다(진행자가 사용자 승인 후 지침으로 올려 다음
책부터 적용). 흔한 판례 자리:

- 축소("판다")의 기준이 처음 산 물량(`bought`)인지 남은 물량(`held`)인지 원문이 안 정함.
- **같은 측정에 저자가 기준 숫자를 둘 준 것**(예: SOXL 5일 상승 2~3일은 20%, 4~5일은 15%) — 이건 **복제가 아니다**
  (`COND_DSL.md` 0절 5). a 는 하나로 뭉치고 b 는 둘로 나눴다면, 저자가 맥락을 달리 줬으니 **둘 다 규칙으로 두고** `note` 로
  구분하는 쪽이 맞다. 같은 식 검사는 값이 다르면 막지 않는다 — 어느 쪽이 원문 맥락에 맞는지 판례로 정하고 `why`.

## 4. 최종 트리 쓰기

`COND_DSL.md` 1·5절 형식에 규칙마다 `why` 를 단다 — a·b 의 식이나 판정이 **다른 모든 규칙**에 왜 그쪽을 골랐는지
원문 근거(인용)로. 같은 쪽을 그대로 쓴 규칙에는 `why` 가 필요 없다.

- `why` 는 원문 근거가 있을 때만 — 정지를 지우려고 쓰지 않는다.
- 판례(원문이 안 정한 갈림)는 `why` 에 "판례:" 로 표시한다.
- 두 쪽에서 정말 옮길 수 없는 것만 `skip` 규칙으로 합친다(`데이터 없음:`·`연산 없음:`).

## 5. 채점과 반복

`python -m verify.verify_tree <slug>` — 정지가 0 이 될 때까지 3~4 를 반복한다(경고는 남아도 되지만 하나씩 이유를 보고).

| 정지 | 뜻 | 고칠 곳 |
|---|---|---|
| 공통 직렬화 아님 | `fmt` 를 안 거침 | `python -m dsl.tradeTool fmt <파일>` |
| 미심판 불일치 | 식이나 판정이 다른 규칙(수동 차이 포함)에 `why` 없음 | 그 규칙에 원문 근거로 `why` |
| 같은 식 두 벌 | 같은 측정이 두 규칙에 각자(값이 같음) | 이름 하나로, 다른 규칙은 `{"rule"}` 참조 |
| 같은 이름 다른 식 | 다른 두 측정이 한 이름 | a·b 의 이름 중 서로 다른 것으로 가른다 |
| 판정이 완전히 같은 조건 | 식은 다른데 3년간 판정이 같은 규칙 쌍 | 같으면 하나로. 저자가 일부러 둘로 썼으면(다른 숫자) 둘 다 두고 `why` 에 판례 |
| 이름 없는 수동 · 사유 머리 없는 skip | 수동/skip 규칙 위반 | a·b 에 맞는 형태가 있으면 그것으로, 없으면 미해결 보고 |
| 사례 불일치 | 원문 사례(그날 결과)를 트리가 재현 못 함 | 트리가 원문과 다르면 트리를, 사례가 원문을 잘못 읽었으면 `why` 에 근거 적고 사례 보고 |
| 종목·심볼 `"?"` 남음 | `products`/`names` 에 근거 없는 `"?"` | 사용자 확인 |
| 식 되는데 skip(충실성) | 식으로 쓸 수 있는 걸 `skip` 함 | 규칙 또는 이름 조건으로 뽑는다 |

## 6. 보고

채점 결과(정지·경고) · 주요 판단과 원문 근거(규칙별 `why`) · 뺀 것과 이유 · **판례(원문이 안 정해 관례로 정한 것 —
지침 승격 후보, 특히 '같은 측정 다른 숫자' 짝)** · 미해결(a·b 어디에도 고칠 재료가 없는 것) · 도구 문제(코드는 고치지
말고 정확히 보고) · 채점 반복 횟수.
