# 조건 트리 문법 (트리를 쓰는 에이전트 — 추출자·심판 — 의 참고서)

조건 트리 = **체크리스트**(`books/<slug>/tree.json`). 이 문서는 트리를 쓰는 추출자(`EXTRACTOR.md`)와 심판(`JUDGE.md`)이
같이 보는 **문법 — 무엇이 유효한가와 그것이 무슨 뜻인가**만 적는다. 어떻게 쓰라는 작성 규칙은 각 역할 문서에 있다.
트리를 쓰지 않는 사례 작성자는 이 문서를 읽지 않는다(`SCENARIO.md` 만).
흔히 쓰는 식을 어떤 모양으로 조합하는가는 문법 사용법이라 맨 끝 6절에 조합 패턴 예시로 둔다.

평가기·등급·사유는 `dsl/tradeTool.py`(Cond=문법 정본 = 그 파일 docstring · Grade=등급·사유), 체결 규약은
`consumers/backtest/trades.py` — 만드는 쪽의 검사와 읽는 쪽의 판정이 **같은 코드**를 쓴다. 문법 밖의 키는 오류로 거부된다.
트리를 만드는 곳은 구간② 하나, 읽는 곳은 구간③(판정 엔진·백테스트) 하나다. 화면은 ③의 판정 결과만 그린다.
트리 파일의 키 배치를 아는 코드는 `dsl/tree_gateway.py`(TreeGateway — 파일 형식 검사·탐색) 하나다 — 판정·백테스트·
검사기는 거기에 묻고 원본 키를 직접 읽지 않는다(`verify/verify_code` 주인 표 '트리 원본 키').

## 0. 핵심 원칙 (먼저 읽는다 — 문법보다 중요하다)

1. **충실성 — 표현 가능한 식은 반드시 추출한다.** 가격·거래량·변동성·이격·변화율·지표·비율·개수·기간·여러 종목 중
   몇 개·내 포지션 수익률 — 무엇을 재든, 숫자가 없어도 **식으로** 쓴다. `skip` 은 식으로 **쓸 수 없는 진짜 잔여**
   (`데이터 없음:`·`연산 없음:`)에만 쓴다. 식이 되는데 skip 하면 검사기가 정지시킨다. 한 문장에 식 되는 조각과
   안 되는 조각이 섞이면 **쪼갠다**(식 조각 = 규칙, 나머지만 skip).
2. **상대 크기는 `qty` 가 아니라 입장(`do`·등급)이다.** "아주 작게·소액만·크게·확대·축소·줄여라"처럼 **숫자 없는 크기
   말**은 금액이 아니라 사라/사지 마라는 판정이다 → `do` 동사로 옮긴다("20일선 아래 쉬거나 아주 작게"→`안 산다`,
   "3점 소액만"→`⚪관망`). `qty` 에 억지로 `"?"` 를 박지 않는다.
3. **모르면 `"?"`.** 조건은 되는데 **숫자만** 저자가 안 줬으면 그 숫자 자리 하나만 `"?"`(🟡 사람이 확인). 추천값·
   기본값·지어낸 숫자는 어디에도 쓰지 않는다(식에도 메모에도).
4. **한 식 = 한 이름.** 같은 측정은 이름 하나로 두고, 다른 규칙은 `{"rule": "이름"}` 으로 참조한다(복제 금지).
5. **같은 측정 다른 숫자는 허용한다.** 저자가 맥락을 달리해 같은 측정에 다른 기준을 줬으면(예: SOXL 5일 상승 2~3일은
   20%, 4~5일은 15%) **둘 다 규칙으로 두고** `note` 로 구분한다. "같은 식 두 벌" 검사는 **값이 다르면 막지 않는다**.
   a·b 가 이런 데서 갈리면 심판의 판례 후보다.

## 1. 규칙의 모양

트리 = **규칙 목록**이다. **원문 판단 하나 = 규칙 하나.** 상품 × 칸 6개의 격자는 없다 — 칸(filter/avoid/entry/
caution/sizing/exit)은 폐지됐다. 행동은 **동사 셋**으로 말한다.

| `do` 동사 | 흡수한 옛 칸 |
|---|---|
| `안 산다` | filter(들어갈 시장 아님) · avoid(살 자리 아님) · caution 의 "줄여라/소액" 중 사지 말라는 쪽 |
| `산다` | entry(살 자리) · sizing(비중·분할) |
| `판다` | exit(매도·축소) |

규칙은 세 종류다. 한 규칙은 이 중 하나다.

- **행동 규칙** — `then` 이 있다: 조건이 맞으면 무엇을 하는지(산다/판다/안 산다).
- **이름 조건(`cond`)** — `then`·`skip` 둘 다 없다: 저자가 **측정만** 주고 행동을 안 줬거나, 여러 규칙이 공유하는
  조각이다. 측정식(`value` 또는 한 갈래의 `when`)만 담고, 다른 규칙이 `{"rule": "이름"}` 으로 가져다 쓴다.
  판정 등급에는 직접 쓰이지 않는다(참조될 때만).
- **skip 규칙** — `skip` 이 있다: 식으로 못 옮긴 진짜 잔여(§0 원칙 1). 행동도 조건도 못 쓴다.

```
{ "version": 3,
  "products": {"TQQQ": {"index": "^NDX", "ref": "1-1"}, ...},
  "names": {"$반도체대표주": {"syms": ["NVDA", "AMD", "AVGO"], "ref": "4-2", "note": "..."}},
  "rules": [
    { "label": ...,            // 조건의 이름 — 대상 + 상태, 행동 단어 안 넣음. 책 안에서 유일
      "ref": ...,  "note"?: ..., // 원문 소절(여럿이면 "·") · 해석/운영 메모(판정엔 안 씀)
      "on"?: [상품],            // 원문이 이름으로 지목한 상품·이름 심볼. 생략 = products 전부
      "value"?: 식,            // 갈래들이 같이 보는 값. 갈래 안에서 "$value"
      "then"?: [{"when": 조건, "do": "안 산다"|"산다"|"판다", "qty"?: {...}, "repeat"?: true}],
      "skip"?: "데이터 없음: …"|"연산 없음: …",
      "why"?: ... }            // 심판이 a·b 중 고른 이유(최종 트리만)
  ] }
```

| 맨 위 필드 | 하는 일 |
|---|---|
| `version` | `3`. 코드가 옛 양식(칸 6개)을 거부 |
| `products` | 판정할 종목 `{index, ref \| note}` — 기준지수(`$index`). 원문이 말했으면 `ref`, 운영 판단이면 `note`, 근거 없으면 `"?"`(검사기 정지 → 사용자 확인) |
| `names` | 이름 심볼 `{syms, ref, note}` — 실제 종목 목록은 여기 한 곳만 |
| `rules` | 규칙 목록 — 원문 판단 하나 = 규칙 하나 |

| 규칙 필드 | 하는 일 |
|---|---|
| `label` | **조건의 이름**(대상 + 상태). 행동 단어("추격 금지"·"매수") 넣지 않는다. 다른 규칙이 이 이름으로 부른다. 책 안에서 유일 |
| `ref`·`note` | 원문 소절(여럿이면 `·`) · 해석/운영 판단 메모(판정엔 안 씀) |
| `on` | 원문이 **이름으로 지목한** 상품·이름 심볼. 생략 = `products` 전부 |
| `value` | 갈래들이 같이 보는 값(있을 때만). 갈래 안에서 `"$value"` 로 참조 |
| `then` | 갈래 목록 `[{when, do, qty?, repeat?}]` — **맞는 갈래 전부** 실행(각 갈래 한 번). 있으면 행동 규칙 |
| `skip` | 못 옮긴 이유 — `"데이터 없음: …"` · `"연산 없음: …"` 뿐. **식이 되면 금지**(§0 원칙 1). "저자 미명시: 행동"은 skip 이 아니라 이름 조건으로 |
| `why` | 심판이 a·b 중 고른 이유(최종 트리만) |

`then`·`skip` 둘 다 없는 규칙이 곧 **이름 조건(`cond`)** 이다 — `value`(또는 한 갈래의 `when`)만 담아 다른 규칙이 참조한다.

| 갈래(`then` 의 한 칸) | 하는 일 |
|---|---|
| `when` | 조건 — 2절 문법 그대로 |
| `do` | `안 산다` · `산다` · `판다` |
| `qty` | 얼마나 `{of, x}`(산다·판다, 저자가 숫자를 준 경우만) |
| `repeat` | `true` = 조건이 다시 맞을 때마다(기본은 한 번) |

### 얼마나 (`qty`)

`qty` 는 **실제 저자가 준 숫자만** 담는 선택 칸이다(없으면 안 쓴다). `of` 는 그 숫자가 **무엇의** 비율인지:

| `of` | 뜻 | 원문 예 |
|---|---|---|
| `cash` | 총 투자금의 x | "비중 30%" |
| `budget` | 이 종목 배정 금액의 x | "25%·30%·45% 로 나눈다" |
| `bought` | 지금까지 산 물량의 x | "산 물량의 30% 매도" · "같은 양 더 산다" |
| `held` | 지금 남은 물량의 x (1 = 전량) | "남은 것 절반" |

`x` = 숫자 · 식 · `"?"`. **행동(판다)은 분명한데 비율만 저자 미명시**면 `x: "?"`(🟡 사람이 답). 조건·행동 자체가
안 되는 것(=skip)과 구별한다. **상대 크기 말("크게/소액")에는 qty 를 쓰지 않는다 — §0 원칙 2.** 그래서 옛
`order`(오늘 사려던 양의 배수)·`scale`(조심 배수) qty 종류는 폐지됐다.

### 조건에 추가되는 것

| 표기 | 뜻 |
|---|---|
| `{"rule": "이름"}` | 그 이름의 조건을 가져다 씀 — 규칙이면 그 `value`(없으면 첫 갈래 `when`) |
| `{"pos": "filled", "rule": "이름"}` | 그 규칙으로 산(판) 횟수 → "1차 다음 2차" · "~할 때마다" |
| `{"pos": "sold"}` | 지금까지 판 비율 → "절반까지만"(`sold < 0.5`) |
| 순위 | 후보 종목 중 이 종목의 순위 → "가장 강한 3개" |
| `"?"` | 저자가 안 준 숫자 — 조건이든 얼마나든 어디서든 |

포지션 값 `pos`: `ret`·`days`·`maxret`·`minret`·`filled`(그 규칙으로 산 횟수)·`sold`(지금까지 판 비율)는 어느
규칙에서든 쓴다 — 보유가 없으면 그 갈래는 평가하지 않는다.

## 2. 노드 문법

```
숫자            3, 1.5        "?" = 저자가 안 준 숫자 — 숫자 자리 어디든(비교 기준·창 길이·lag·sum 기간·atleast 개수)
시세            {"px": "close"|"open"|"high"|"low"|"volume", "sym": "$self", "tf": "1d"}   sym 생략 = $self, tf 생략 = 1d
산술            {"add"|"sub"|"mul"|"div"|"max"|"min": [a, b]}      max/min = 같은 날 두 값 중 큰/작은 값
                {"abs": a}
선택            {"case": [[c1, v1], [c2, v2], ...], "else": v}     위에서부터 처음 참인 조건의 값(앞 조건이 모름이면 결과도 모름)
창              {"highest"|"lowest"|"sum": [s, n]}    n 봉(오늘 포함)
                {"lag": [s, k]}   k 봉 전 값        {"pct": [s, k]}   k 봉 전 대비 %
비교            {"gt"|"ge"|"lt"|"le": [a, b]}
논리            {"all": [..]} {"any": [..]} {"atleast": n, "of": [..]} {"not": c}
시간            {"count": [c, n]}      최근 n봉(오늘 포함) 중 c 참인 봉 수
                {"streak": c}          오늘부터 거꾸로 c 가 연속 참인 봉 수
                {"barssince": c}       c 가 마지막으로 참이었던 봉부터 지난 봉 수(오늘 참 = 0)
                {"valuewhen": [c, s]}  c 가 마지막으로 참이었던 봉의 s
                {"minsince"|"maxsince": [c, s]}  그 봉부터 오늘까지 s 의 최저/최고
여러 종목       {"across": {"syms": [..], "cond": c}}   c 참인 종목 수 — c 안에서 "$s" = 그 종목
수동            {"manual": "사유"}
포지션          {"pos": "ret"|"days"|"maxret"|"minret"|"filled"|"sold"}   보유가 없으면 그 갈래 평가 안 함
이름 참조       {"rule": "이름"}   (다른 규칙 또는 이름 조건)
메타            "label"(사람이 읽을 이름), "ref"(원문 소절 키, 예 "3-1"), "note"
```

- **3값 논리**: 값은 날짜별 시계열이고 데이터가 없으면 모름(None)이다 — 조용히 거짓으로 치지 않는다.
- **같은 식 = 같은 조건**: 조건의 신원은 식이다(META 를 떼고 정규화 — 시세 기본값 생략, a<b ↔ b>a, 묶음 안 순서 무관).
  단 **값(기준 숫자)이 다르면 다른 조건**이다(§0 원칙 5 — 같은 측정 다른 숫자 허용).
- **수동 잎** = 사람이 참/거짓을 정하는 잎: ① `"?"` 를 품은 판단 노드(비교의 양쪽 식 어디든 `"?"`, 또는 atleast 의
  n 이 `"?"`) ② 문장 수동 `{"manual": "사유"}`. 엔진은 수동을 '확인되면/안 되면' 두 번 평가한다 — 확인 안 돼도
  산다 → ✅, 확인돼야 산다 → 🟡 확인 대기, 확인돼도 안 됨 → 그 사유 등급. **극성**: not 아래의 수동은 반대 값을 받는다.
- **문장 수동의 사유 머리**: `데이터 없음:`(계산할 값이 없음 — 수집 과제) · `연산 없음:`(값은 있는데 계산 도구가 없음).
  "저자 미명시: 행동"은 문장 수동이 아니라 **이름 조건(`cond`)** 으로 남긴다(식이 트리에 살아 참조된다).

## 3. 관측 시점 · 봉 · 심볼

- **관측 시점(asof)**: 판정은 사용자가 보는 그 순간 기준이다(라이브 = 지금 또는 지정 시각, 백테스트 = 재생되는 각 시점).
  각 값은 asof 로 자른다 — asof 이하의 값만 쓰므로 미래를 볼 수 없다. 값이 없으면(데이터 미연결·결측) 모름.
  `python -m entry.run watch [--every N]` 가 asof=지금으로 N분마다 재판정한다.
- **봉(`tf`)**: 시세 노드의 속성 — `"1d"`(일봉, 기본 · asof 이하 마지막 확정 일봉) · `"1m"`(분봉) · `"5m"`(5분봉).
  창·시간 연산의 n·k 는 그 노드가 도는 봉 기준으로 센다.
- **심볼**: `$self` = 그 상품, `$index` = 상품의 기준 지수(상품의 `index` 필드), `$s` = across 안의 종목, 이름 심볼
  (`$반도체대표주`)은 `names` 가 정의, 그 외는 jhts 심볼 코드 그대로 — 미국은 야후 심볼(`^NDX` `^GSPC` `^VIX`
  `^TNX`(10년물 금리, 값 = %) `NQ=F` `KRW=X`, 종목·ETF 티커), 국내는 6자리 종목코드. 지수는 거래량이 0/결측일 수 있다.
- **수집**: 수집 요청서는 따로 없다 — 구간③이 `TreeGateway.symbols()` 로 심볼을 뽑아 `market/md_feed.histories()` 에서
  받는다. 시세가 없는 심볼은 jhts 수집 요청을 자동으로 남기고 그 판정은 ❔ "시세 없음(수집 요청 #id)"으로 드러난다.

## 4. 규칙·갈래 형식

행동 규칙은 `then` 에 갈래를 담고, 갈래마다 `when`(조건)·`do`(동사)·`qty`(얼마나, 선택)·`repeat`(선택)를 쓴다.
**맞는 갈래 전부**가 실행된다(각 갈래 한 번, `repeat: true` 면 조건이 맞을 때마다).

- **산다·판다**: 저자가 비율을 줬으면 `qty: {of, x}`(1절). 안 줬으면 — 행동은 분명한데 비율만 모르면 `x: "?"`,
  크기 말("크게/소액")뿐이면 **qty 를 쓰지 말고** 입장(`do`·등급)으로(§0 원칙 2).
- **안 산다**: `qty` 없음(사지 말라는 데 수량은 없다).
- **분할·차수**: "1차 다음 2차"는 `{"pos": "filled", "rule": "1차 이름"}` 으로 앞 차수를 산 횟수를 조건에 건다
  (앞 차수를 안 샀으면 뒤 갈래는 평가되지 않는다). 각 차수의 `qty.of` 는 보통 `budget`.
- **매도·축소**: "판다·축소·정리"라는 말이 있어야 판다 규칙이다("재판단"·"검문"처럼 판다는 말이 없으면 옮기지 않는다).
  구간("7~10%")으로 말하면 처음 닿는 하한(7)으로 쓰고 `note` 에 적는다. 안전장치(저자가 안 준 손절·기간만료)를 끼우지 않는다.

**이름 조건(`cond`)** 은 `then`·`skip` 없이 `value`(또는 한 갈래의 `when`)만 담는다 — 저자가 측정만 주고 행동을
안 줬거나, 둘 이상의 규칙이 공유하는 조각이다. **skip** 은 `데이터 없음:`·`연산 없음:` 잔여에만(§0 원칙 1).

## 5. 파일 형식

```json
{
  "version": 3,
  "products": {
    "TQQQ": {"index": "^NDX", "ref": "1-1"},
    "SOXL": {"index": "^SOX", "ref": "1-1"}
  },
  "names": {
    "$반도체대표주": {"syms": ["NVDA", "AMD", "AVGO"], "ref": "4-2", "note": "운영 판단: '대표주' = 3종"}
  },
  "rules": [
    {"label": "...", "ref": "...", "then": [{"when": 조건, "do": "산다", "qty": {"of": "budget", "x": 0.25}}]},
    {"label": "...", "ref": "...", "value": 식, "then": [{"when": 조건, "do": "판다"}]},
    {"label": "...", "ref": "...", "value": 식},
    {"label": "...", "ref": "...", "skip": "연산 없음: 계좌 전체 기준"}
  ]
}
```

- `version` 은 `3`. `products`·`names` 의 종목·심볼에 `"?"` 가 남으면 검사기가 정지한다(사용자 확인).
- 최종 트리(심판)만 규칙에 `why` 를 단다. 추출자 트리에는 `why` 가 없다.

**직렬화**: 트리 파일을 쓴 뒤 반드시 `python -m dsl.tradeTool fmt <파일>` 로 공통 형식(`cond.compact_json` —
한 줄에 들어가는 노드는 한 줄, 숫자 목록은 이어 붙임)으로 다시 쓴다. 들여쓰기로 줄 수를 부풀리지 않는다 —
형식이 다르면 `verify_tree` 가 정지한다.

## 6. 흔한 식 — 조합 패턴 (C = `{"px":"close"}`, V = `{"px":"volume"}`)

지표를 하나씩 전용 연산으로 만들지 않는다 — **기본 부품을 조합**한다. (ma·ema·stdev·rsi·pct·count·streak 같은 전용
연산을 줄이는 중이다. 아래 모양으로 조합한다.)

| 원문 | 식 |
|---|---|
| 무엇을 보나 | 원문이 지목한 대상 그대로: "나스닥이/지수가" → `$index`, "TQQQ가/이 ETF가" → 상품 자신(`sym` 생략), 특정 종목 → 그 티커 |
| 상품 자신의 종가 | `{"px":"close"}` — `"sym":"$self"`·`"tf":"1d"` 는 적지 않는다(기본값) |
| N일 평균 | `{"div":[{"sum":[C,N]},N]}` — 전용 `ma` 안 쓴다 |
| N일선 위 / 아래 | `{"gt":[C,{"div":[{"sum":[C,N]},N]}]}` / `{"lt":[...]}` |
| 연속 N일 참 | `{"ge":[{"streak":조건},N]}` |
| N일 동안 x% 올랐다 | `{"ge":[{"pct":[C,N]},x]}` |
| 전일 대비 x% | `{"pct":[값,1]}` |
| 최근 n일 중 상승일 m일 이상 | `{"ge":[{"count":[{"gt":[C,{"lag":[C,1]}]},n]},m]}` |
| 전고점(최근 N일 최고) | P = `{"highest":[{"lag":[C,1]},N]}` — N 미명시면 `"?"` |
| 돌파 · 돌파선 고정 · 버팀 · 경과일 | 돌파 = `{"gt":[C,P]}` · 돌파선 = `{"valuewhen":[돌파,P]}` · 버팀 = `{"gt":[{"minsince":[돌파,C]},돌파선]}` · 경과일 = `{"add":[{"barssince":돌파},1]}` |
| 윗꼬리 길이 | `{"sub":[{"px":"high"},{"max":[{"px":"open"},C]}]}` |
| 거래량 과다 | `{"ge":[{"div":[V,{"div":[{"sum":[V,N]},N]}]},k]}` · 전일 대비 `{"div":[V,{"lag":[V,1]}]}` — 지수는 거래량이 없을 수 있으니 거래되는 종목으로 |
| **N개 중 M개 이상(점수표)** | `{"atleast":M,"of":[조각1, 조각2, ...]}` — **`sum(case)` 중첩으로 세지 않는다**. "넷 중 둘" = `{"atleast":2,"of":[...]}` |
| N개 중 몇 개인지 미명시 | `{"atleast":"?","of":[...]}` |
| 여러 종목 중 몇 개 | `{"ge":[{"across":{"syms":[...],"cond":{"gt":[{"px":"close","sym":"$s"},{"lag":[{"px":"close","sym":"$s"},1]}]}}},n]}` |
| 조건을 숫자로(상승일이면 1) | `{"case":[[{"gt":[C,{"lag":[C,1]}]},1]],"else":0}` — "하락일 낙폭 합 > 상승일 상승폭 합" = 그렇게 만든 값의 `sum` 비교 |
| 내 포지션 수익률 | `{"pos":"ret"}` (보유가 없으면 그 갈래 평가 안 함) |
| 이 규칙으로 산 횟수 | `{"pos":"filled","rule":"1차 이름"}` — "1차 다음 2차"·"~할 때마다" |
| 지금까지 판 비율 | `{"pos":"sold"}` — "절반까지만" = `{"lt":[{"pos":"sold"},0.5]}` |
| 다른 규칙의 측정을 가져다 씀 | `{"rule":"이름"}` — 같은 측정은 이름 하나, 복제하지 않는다 |

**점수표는 `atleast` 로.** 옛 `count`/`sum(case)` 중첩으로 "N개 중 M개"를 세던 괴물식을 쓰지 않는다 —
각 조각을 `of` 배열에 나열하고 `atleast` 에 M 을 둔다. 조각이 다른 규칙과 겹치면 `{"rule":"이름"}` 으로 참조한다.

표에 없는 개념은 위 모양을 조합한다. 같은 책 안에서 같은 개념은 한 모양으로만 쓴다(단 저자가 기준 숫자를
달리 줬으면 그건 다른 조건이다 — §0 원칙 5).
