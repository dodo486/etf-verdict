# 조건 트리 문법 (트리를 쓰는 에이전트 — 추출자·심판 — 의 참고서)

조건 트리 = **체크리스트**(`books/<slug>/tree.json`). 이 문서는 트리를 쓰는 추출자(`EXTRACTOR.md`)와 심판(`JUDGE.md`)이
같이 보는 **문법 — 무엇이 유효한가와 그것이 무슨 뜻인가**만 적는다. 어떻게 쓰라는 작성 규칙은 각 역할 문서에 있다.
트리를 쓰지 않는 사례 작성자는 이 문서를 읽지 않는다(`SCENARIO.md` 만).
흔히 쓰는 식을 어떤 모양으로 조합하는가는 문법 사용법이라 맨 끝 6절에 조합 패턴 예시로 둔다.

평가기는 `checklist/cond.py`(문법 정본 = 그 파일 docstring), 등급·사유는 `checklist/grade.py`, 체결 규약은
`consumers/backtest/trades.py` — 만드는 쪽의 검사와 읽는 쪽의 판정이 **같은 코드**를 쓴다. 문법 밖의 키는 오류로 거부된다.
트리를 만드는 곳은 구간② 하나, 읽는 곳은 구간③(판정 엔진·백테스트) 하나다. 화면은 ③의 판정 결과만 그린다.
트리 파일의 키 배치를 아는 코드는 `dsl/tree_gateway.py`(TreeGateway — 파일 형식 검사·탐색) 하나다 — 판정·백테스트·
검사기는 거기에 묻고 원본 키를 직접 읽지 않는다(`orchestration/verify_code` 주인 표 '트리 원본 키').

## 1. 여섯 칸 — 상품마다

| 칸 | 묻는 것 | 형식 | 결과 |
|---|---|---|---|
| `filter` | 들어가도 되는 시장인가 | 조건 | 거짓 → 🚫 진입 금지 |
| `avoid` | 사면 안 되는 자리인가 | 조건 | 참 → ⛔ 보류 |
| `entry` | 살 자리인가 | 조건 | 참 → ✅ 매수 후보, 거짓 → ⚪ 관망 |
| `caution` | 사더라도 금액을 줄일까 | 규칙 목록(4절) | 걸린 규칙마다 금액 × `scale` |
| `sizing` | 얼마나·나눠서 | 값 + 분할 목록(4절) | 총 투자금 대비 % · 차수별 비율 |
| `exit` | 보유분을 언제 얼마나 팔까 | 규칙 목록(4절) | 걸리면 다음 봉 시가에 매도 |

- 여섯 칸 모두 **반드시** 있다(빠진 칸을 조용히 기본값으로 채우지 않는다). 비어 있음의 표기:
  `filter`/`entry` = `{"all": []}`(항상 참), `avoid` = `{"any": []}`(항상 거짓), `caution`·`exit` = `[]`,
  `sizing` = `{"weight": null, "tranches": []}`.
- **판정 시점 = 사용자가 보는 그 순간(asof)** — 장 전·장중·장 후 언제든(3절). 백테스트의 체결은 판정 다음 봉 시가.
- 여러 상품이 같이 쓰는 노드는 최상위 `defs` 에 한 번 두고 `{"def": "이름"}` 으로 참조한다. `defs` 노드에 `label` 이
  있고 상품 둘 이상이 쓰면 화면 맨 위 '공통 조건'에 한 번 보인다.

## 2. 노드 문법

```
숫자            3, 1.5        "?" = 저자가 안 준 숫자 — 숫자 자리 어디든(비교 기준·창 길이·lag·count 기간·atleast 개수)
시세            {"px": "close"|"open"|"high"|"low"|"volume", "sym": "$self", "tf": "1d"}   sym 생략 = $self, tf 생략 = 1d
산술            {"add"|"sub"|"mul"|"div"|"max"|"min": [a, b]}      max/min = 같은 날 두 값 중 큰/작은 값
                {"abs": a}
선택            {"case": [[c1, v1], [c2, v2], ...], "else": v}     위에서부터 처음 참인 조건의 값(앞 조건이 모름이면 결과도 모름)
창              {"ma"|"ema"|"stdev"|"highest"|"lowest"|"sum": [s, n]}   n 봉(오늘 포함)
                {"lag": [s, k]}   k 봉 전 값        {"pct": [s, k]}   k 봉 전 대비 %
                {"rsi": [s, n]}
비교            {"gt"|"ge"|"lt"|"le": [a, b]}
논리            {"all": [..]} {"any": [..]} {"atleast": n, "of": [..]} {"not": c}
시간            {"count": [c, n]}      최근 n봉(오늘 포함) 중 c 참인 봉 수
                {"streak": c}          오늘부터 거꾸로 c 가 연속 참인 봉 수
                {"barssince": c}       c 가 마지막으로 참이었던 봉부터 지난 봉 수(오늘 참 = 0)
                {"valuewhen": [c, s]}  c 가 마지막으로 참이었던 봉의 s
                {"minsince"|"maxsince": [c, s]}  그 봉부터 오늘까지 s 의 최저/최고
여러 종목       {"across": {"syms": [..], "cond": c}}   c 참인 종목 수 — c 안에서 "$s" = 그 종목
수동            {"manual": "사유"}
포지션          {"pos": "ret"|"days"|"maxret"|"minret"}   exit 와 sizing 의 2차 이후 분할에서만 · def 에 둘 수 없다
재사용          {"def": "이름"}   (최상위 defs 에 정의)
메타            "label"(사람이 읽을 이름), "ref"(원문 소절 키, 예 "3-1"), "id", "note"
```

- **3값 논리**: 값은 날짜별 시계열이고 데이터가 없으면 모름(None)이다 — 조용히 거짓으로 치지 않는다.
- **같은 식 = 같은 조건**: 조건의 신원은 식이다(META 를 떼고 정규화 — 시세 기본값 생략, a<b ↔ b>a, 묶음 안 순서 무관).
- **수동 잎** = 사람이 참/거짓을 정하는 잎: ① `"?"` 를 품은 판단 노드(비교의 양쪽 식 어디든 `"?"`, 또는 atleast 의 n 이
  `"?"`) ② 문장 수동 `{"manual": "사유"}`. 엔진은 수동을 '확인되면/안 되면' 두 번 평가한다 — 확인 안 돼도 매수 → ✅,
  확인돼야 매수 → 🟡 확인 대기, 확인돼도 안 됨 → 그 사유 등급. **극성**: not 아래의 수동은 반대 값을 받는다.
  화면은 `"?"` 비교의 알려진 쪽 값을 근거 숫자로 보여준다.
- **문장 수동의 사유 머리**: `저자 미명시:`(수치로 정할 수 없는 순수 주관 — `(정성)` 표시) · `데이터 없음:`(계산할 값이
  없음 — 수집·연결 과제) · `연산 없음:`(값은 있는데 계산 도구가 없음 — 원시 연산 추가 과제).

## 3. 관측 시점 · 봉 · 심볼

- **관측 시점(asof)**: 판정은 사용자가 보는 그 순간 기준이다(라이브 = 지금 또는 지정 시각, 백테스트 = 재생되는 각 시점).
  각 값은 asof 로 자른다 — asof 이하의 값만 쓰므로 미래를 볼 수 없다. 값이 없으면(데이터 미연결·결측) 모름.
  `python -m entry.run watch [--every N]` 가 asof=지금으로 N분마다 재판정한다.
- **봉(`tf`)**: 시세 노드의 속성 — `"1d"`(일봉, 기본 · asof 이하 마지막 확정 일봉) · `"1m"`(분봉) · `"5m"`(5분봉).
  창·시간 연산의 n·k 는 그 노드가 도는 봉 기준으로 센다.
- **심볼**: `$self` = 그 상품, `$index` = 상품의 기준 지수(상품의 `index` 필드), `$s` = across 안의 종목, 그 외는 jhts
  심볼 코드 그대로 — 미국은 야후 심볼(`^NDX` `^GSPC` `^VIX` `^TNX`(10년물 금리, 값 = %) `NQ=F` `KRW=X`, 종목·ETF
  티커), 국내는 6자리 종목코드. 지수는 거래량이 0/결측일 수 있다.
- **수집**: 수집 요청서는 따로 없다 — 구간③이 `TreeGateway.symbols()` 로 심볼을 뽑아 `shared/md_feed.histories()` 에서
  받는다. 시세가 없는 심볼은 jhts 수집 요청을 자동으로 남기고 그 판정은 ❔ "시세 없음(수집 요청 #id)"으로 드러난다.

## 4. 규칙 칸의 형식

**caution** — `[{"label", "ref", "when": 조건, "scale": 숫자|null}]`. 매수 판단과 따로 평가하고, 걸린 규칙마다 그날
금액에 `scale` 을 곱한다. `null` = 폭 미명시(화면에 "줄일 폭 저자 미명시", 금액 계산은 사람이).

**sizing** — `{"label", "ref", "weight": 숫자 식|null, "tranches": [{"label", "ref", "frac": 숫자|null, "when"?: 조건}]}`.
`weight` = 총 투자금 대비 이 상품 비중(%). 상품들의 `weight` 합은 어느 날이든 100 을 넘지 못한다(검사기 정지) —
현금 = 100 − 합(판정 단계가 계산). `frac` 합은 1, 또는 전부 `null`(일부만 숫자는 안 된다 — 백테스트는 전량 한 번
매수로 계산하고 그렇게 표시). 1차는 `when` 없이 매수 신호(✅·🟡) 날, 2차 이후는 `when` 이 참인 날 다음 봉 시가에
차례대로 산다(앞 차수를 안 샀으면 뒤 차수도 안 산다). `[]` = 한 번에 전량.

**exit** — `[{"label", "ref", "when": 조건, "sell": "all"|{"initial": f}|{"remaining": f}, "note"?}]`. 보유 포지션에 대해
봉마다 평가하고 걸리면 다음 봉 시가에 판다. 규칙마다 한 번만 적용된다. `sell`: `"all"` 남은 전량 · `initial` 그때까지
산 물량의 f · `remaining` 남은 물량의 f. f 를 저자가 안 줬으면 `null`("축소"만 말함 — 화면엔 비율 ?, 백테스트는 팔지 않은 것으로
계산하고 그렇게 표시). 포지션 값: `{"pos": "ret"}` 평균 매입가 대비 수익률(%) · `"days"` 첫 매수일부터
지난 봉 수 · `"maxret"`/`"minret"` 첫 매수 후 수익률의 최고/최저.


## 5. 파일 형식

**트리**(`tree.json` · 후보 `tree_candidates/<a|b>.json`):

```json
{
  "version": 2,
  "source": {"book": "<slug>", "extractor": "a|b|심판", "sections_read": ["3-1", "..."]},
  "defs": {"<이름>": 노드},
  "products": {
    "TQQQ": {"index": "^NDX", "note": "...",
             "filter": 조건, "avoid": 조건, "entry": 조건,
             "caution": [...], "sizing": {...}, "exit": [...]}
  },
  "unexpressed": [{"rule": "...", "ref": "x-y", "reason": "저자 미명시: …|데이터 없음: …|연산 없음: …"}],
  "review": {...}
}
```

`review` 는 최종 트리에만 있다 — 심판의 판정 근거(형식은 `JUDGE.md`). 구간② 검사기만 읽고 판정·체결엔 쓰지 않는다.

**직렬화**: 트리 파일을 쓴 뒤 반드시 `python -m dsl.tradeTool fmt <파일>` 로 공통 형식(`cond.compact_json` —
한 줄에 들어가는 노드는 한 줄, 숫자 목록은 이어 붙임)으로 다시 쓴다. 줄 수를 부풀리는 들여쓰기를 쓰지 않는다 —
형식이 다르면 `verify_tree` 가 정지한다.

## 6. 흔한 식 — 조합 패턴 (C = `{"px":"close"}`, V = `{"px":"volume"}`)

| 원문 | 식 |
|---|---|
| 무엇을 보나 | 원문이 지목한 대상 그대로: "나스닥이/지수가" → `$index`, "TQQQ가/이 ETF가" → 상품 자신(`sym` 생략), 특정 종목 → 그 티커 |
| 상품 자신의 종가 | `{"px":"close"}` — `"sym":"$self"`·`"tf":"1d"` 는 적지 않는다(기본값) |
| N일선 위 / 아래 | `{"gt":[C,{"ma":[C,N]}]}` / `{"lt":[...]}` |
| 오늘 N일선 회복(어제는 아래) | `{"all":[{"gt":[C,{"ma":[C,N]}]},{"le":[{"lag":[C,1]},{"lag":[{"ma":[C,N]},1]}]}]}` |
| 연속 N일 참 | `{"ge":[{"streak":조건},N]}` |
| "회복 후 k일 유지" | `{"ge":[{"streak":{"gt":[C,{"ma":[C,N]}]}},k+1]}` (회복한 날 포함 — 예: 2거래일 유지 = 3) |
| N일선 이격 % | `{"mul":[100,{"sub":[{"div":[C,{"ma":[C,N]}]},1]}]}` — "근처"는 `{"le":[{"abs":이격},"?"]}` |
| N일 동안 x% 올랐다 | `{"ge":[{"pct":[C,N]},x]}` |
| 전일 대비 x% | `{"pct":[값,1]}` |
| 최근 n일 중 상승일 m일 이상 | `{"ge":[{"count":[{"gt":[C,{"lag":[C,1]}]},n]},m]}` |
| 전고점(최근 N일 최고) | P = `{"highest":[{"lag":[C,1]},N]}` — N 미명시면 `"?"` |
| 돌파 · 돌파선 고정 · 버팀 · 경과일 | 돌파 = `{"gt":[C,P]}` · 돌파선 = `{"valuewhen":[돌파,P]}` · 버팀 = `{"gt":[{"minsince":[돌파,C]},돌파선]}` · 경과일 = `{"add":[{"barssince":돌파},1]}` |
| 고점 이후 눌림 일수(어제까지) | `{"lag":[{"barssince":{"ge":[C,{"highest":[C,N]}]}},1]}` |
| 윗꼬리 길이 | `{"sub":[{"px":"high"},{"max":[{"px":"open"},C]}]}` |
| 거래량 과다 | `{"ge":[{"div":[V,{"ma":[V,N]}]},k]}` · 전일 대비 `{"div":[V,{"lag":[V,1]}]}` — 지수는 거래량이 없을 수 있으니 거래되는 종목으로 |
| 여러 종목 중 몇 개 | `{"ge":[{"across":{"syms":[...],"cond":{"gt":[{"px":"close","sym":"$s"},{"lag":[{"px":"close","sym":"$s"},1]}]}}},n]}` |
| 조건을 숫자로(상승일이면 1) | `{"case":[[{"gt":[C,{"lag":[C,1]}]},1]],"else":0}` — "하락일 낙폭 합 > 상승일 상승폭 합" = 그렇게 만든 값의 `sum` 비교 |
| N개 중 몇 개인지 미명시 | `{"atleast":"?","of":[...]}` |
| 내 포지션 수익률 | `{"pos":"ret"}` (매도·분할 규칙 안에서만 — def 에 못 둔다) |

표에 없는 개념은 위 모양을 조합한다. 같은 책 안에서 같은 개념은 한 모양으로만 쓴다.
